# MCP / Playwright Browser Automation Patterns

Stack-specific patterns for MCP Playwright (claude-in-chrome), FastMCP servers, and browser automation QA. Loaded on-demand via `@import` in project CLAUDE.md files that use browser automation.

---

## MCP Playwright

- **Use snapshot refs over text selectors in crowded layouts**: When multiple elements share the same visible text (e.g., a filter pill "Recipes" and a dropdown option "Recipes" both in the DOM), `locator('text=Recipes')` causes "strict mode violation". Capture a fresh snapshot, identify the exact `[ref=eNNN]` for the target, and click by ref. Snapshot refs are unambiguous; text selectors are not when the same label appears in multiple components. (confidence: HIGH, source: Slate slice 9 — TagPicker click hit NoteList filter instead of dropdown, date: 2026-05-07)
- **Interact with modals/overlays via browser_evaluate + querySelector**: Fixed-position overlays (bottom sheets, modals, popovers) are sometimes absent or flattened in the accessibility snapshot tree. Use `browser_evaluate` with `document.querySelector('[style*="position: fixed"]')` to find the overlay, then `.querySelectorAll('button')` + `.click()` to interact. More reliable than snapshot-based targeting for dynamically-rendered overlays. (confidence: HIGH, source: Slate slice 9 — MobileTagPicker bottom sheet, date: 2026-05-07)
- **`PLAYWRIGHT_JSON_OUTPUT_NAME` env-var bypasses rtk stdout truncation**: rtk's stdout passthrough mangles Playwright JSON output mid-string at ~14KB, breaking `json.loads()`. The reliable parse path is `PLAYWRIGHT_JSON_OUTPUT_NAME=/tmp/x.json npx playwright test ... --reporter=json > /dev/null 2>&1; python3 -c "import json; r = json.load(open('/tmp/x.json'))"` — Playwright writes the full untruncated JSON to the env-named file regardless of stdout. Complements the `--reporter=line` workaround (single-pass list output rtk passes through cleanly) — use line for human-readable runs, env-var JSON for parseable per-test status. (confidence: HIGH, source: confirmed across 2 sessions on 1 project; pattern is stack-portable to any rtk + Playwright setup, date: 2026-05-06 → 2026-05-08)
- **Programmatic input value changes need the native prototype setter to trigger React onChange**: React 18+ controlled `<input>`/`<textarea>` listens on the prototype `value` setter, not on direct `el.value = x`. Setting `el.value = "foo"` then dispatching `new Event('change')` updates the DOM visually but DOES NOT update React state — the synthetic onChange handler never fires. Same failure for Playwright's `browser_type` / `pressSequentially` against controlled inputs (DOM updates, React state stays empty, form submission sends old/empty value). Fix: `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set.call(el, value); el.dispatchEvent(new Event('input', { bubbles: true }))`. Note: must use `'input'` event (not `'change'`) and `bubbles: true`. For `<textarea>`, use `HTMLTextAreaElement.prototype` instead. Detection: if the field's value visually updates but a `submit` button stays disabled (controlled-form validation didn't see the change) or the API receives an empty string, this is the bug. (confidence: HIGH, source: confirmed across 2 projects, date: 2026-04-17 → 2026-05-06)
- **`browser_evaluate` runs as plain JavaScript, not TypeScript**: TS syntax in the function body (type casts like `(x as any).foo`, type annotations like `: string`, `as const`) throws `SyntaxError: Unexpected identifier`. Strip every TS construct before passing the function. Use `el.style.getPropertyValue('-webkit-line-clamp')` instead of casting to `any`; use runtime `typeof`/`in` checks instead of type guards. (confidence: HIGH, source: 1 project but applies to all MCP Playwright callers, date: 2026-05-08)
- **Chrome user-data-dir lock recovery**: After `browser_close` returns "no open tabs", a stale Chrome process can still hold `~/Library/Caches/ms-playwright/mcp-chrome-*/` and the next `browser_navigate` fails with "Browser is already in use". The lock file `SingletonLock` is a symlink whose target is `<hostname>-<PID>`. Recovery: `pgrep -lf mcp-chrome` to find the live PID, `ps -p <PID>` to confirm it's still running, then `pkill -9` (with user consent). Do NOT blindly add `--isolated` — it loses state across QA steps. Do NOT just delete the lock — a live Chrome will recreate it. (confidence: HIGH, source: confirmed 2× on same project, date: 2026-05-08 → 2026-05-10)
- **`browser_navigate(url)` is a hard reload — wipes in-memory state**: For QA flows that depend on persisted-across-navigation state (Zustand, Context, refs without persist middleware), use SPA navigation (click an in-app tab via `getByRole('button')` etc.) to preserve state. A failing assertion that immediately follows `browser_navigate` may be a test-harness artifact, not a real bug — re-run via SPA nav before filing. Document the divergence in plan Branch Points if false-fail risk is high. (confidence: HIGH, source: 1 project but applies to all MCP Playwright users, date: 2026-05-10)
- **MCP Playwright HTTP cache survives `browser_close` — use CDP `Network.setCacheDisabled` for true cache bypass**: The Chromium context's HTTP cache persists across tabs (and across `browser_navigate` calls), so when a dev server's `Cache-Control` header *changes* (e.g. `immutable` → `no-store`), the browser still serves the old entry it cached under the old header. Symptom: the dev server now sends correct `Cache-Control: no-store`, `curl` returns the new chunk content, `fetch(url, {cache:'no-store'})` from inside the page returns the new content, but `document.querySelector` STILL reflects the old running JS module. Cause: the V8 / module cache references the chunk *already loaded into memory* under the old policy. Fix: use `browser_run_code_unsafe` to open a CDP session and disable cache + purge it before reloading: ```js const client = await page.context().newCDPSession(page); await client.send('Network.setCacheDisabled', { cacheDisabled: true }); await client.send('Network.clearBrowserCache'); await page.reload({ waitUntil: 'networkidle' });```. This is the only reliable bypass when (a) dev cache headers just changed, or (b) chunk URLs are path-based and content has changed in-place (Turbopack — see Next.js App Router section). Cheap diagnostic: if your `evaluate` shows the React fiber's `memoizedState` already has the new auth value but the DOM still renders the old conditional branch, the running JS module is the problem — apply the CDP fix. (confidence: HIGH, source: 1 project but applies to any MCP Playwright + Next.js/Vite dev-cache change, date: 2026-05-24)
- **`window.fetch` counter > network log for "fired exactly once" assertions**: `browser_network_requests` can show one application-level `fetch` as two numbered entries (request + response, or a Vite proxy hop) — counting log entries is unreliable proof of "fired once". Install a wrapper before the action: `const orig = window.fetch; window.__fetchCount = 0; window.fetch = (u, o) => { if ((o?.method ?? 'GET').toUpperCase() === 'DELETE') window.__fetchCount++; return orig(u, o); };`, then assert `window.__fetchCount === 1`. The counter is the application-level ground truth. (confidence: HIGH, source: 1 project but applies to all MCP Playwright + write-once QA, date: 2026-05-10)
- **MCP-driven auth setup for cookie + zustand-persist SPAs requires BOTH cookie AND persist-storage entry**: When the SPA uses zustand `persist` middleware to cache the `user` in localStorage alongside cookie-based JWT auth, setting only `document.cookie = 'access_token=...'` is insufficient — `onRehydrateStorage` fires with no user data → store thinks user is unauthenticated → route guard redirects to `/login` before the in-flight `/me` call can hydrate. Set both in a single `browser_evaluate` shot, then navigate: `document.cookie = 'access_token=...; path=/; max-age=86400'; localStorage.setItem('<persist-key>', JSON.stringify({state: {user: <ADMIN_USER_OBJ>}, version: <N>}));`. The persist-key and version must match the store's `persist({name, version})` config. Also remember to clear any leftover `refresh_token` cookie or the response interceptor will auto-refresh back to whatever user that refresh token belongs to. JWTs from earlier sessions can become invalid (secret rotation on dev-server restart, or expiry) — re-mint via `create_access_token(<uuid>)` at the start of every QA browser session. (confidence: HIGH, source: confirmed 3× same project, stack-portable to any Next.js + zustand-persist + cookie-auth SPA, date: 2026-05-25)
- **`page.addInitScript(() => localStorage.clear())` re-fires on EVERY navigation including `page.reload()` — it wipes the very state a persist-across-reload test asserts**: a `beforeEach` that clears storage via `addInitScript` silently breaks the one spec that reloads and expects data to survive (symptom: 3/4 green, the reload test red). Playwright already gives each test an ISOLATED browser context (fresh `localStorage`), so the manual clear is usually unnecessary — drop it, or clear ONCE via `page.evaluate` after the first `goto` instead of an init script. Distinct from the app-wipes-your-token trap (that's the APP's init-time reset undoing your seed); this is the TEST's own clear re-running on reload. (confidence: HIGH, source: 1 project, date: 2026-07-01)

## MCP Servers (FastMCP)

- **MCP servers must start BEFORE the backend for auto-reconnect**: `reconnect_all` runs once at startup. If any MCP server is down at that moment, its tools are silently missing at runtime (tool returns "not found"). Correct start order: MCP servers first, then backend. If order was wrong: restart backend or reconnect via UI. (confidence: HIGH, source: multiple projects — repeated across 2 sessions, date: 2026-03-10)
- **`list[dict]` params generate `additionalProperties:true` schema → LLM skips them**: FastMCP infers JSON Schema from function type hints. `list[dict]` yields `{"items": {}, "additionalProperties": true}` — LLM treats it as optional freeform and often omits it entirely. Use Pydantic models so FastMCP generates a full named schema with required fields the LLM must fill. (confidence: HIGH, source: multiple projects — tool param always missing, date: 2026-03-09)
- **LLM constructs IDs from known fields instead of using returned IDs**: When search results return opaque IDs, LLM in subsequent turns often reconstructs a plausible-looking ID rather than copying the actual returned value. Two defenses: (1) make IDs human-readable with embedded context, (2) add fuzzy fallback lookup on the server side. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **FastMCP transport options — SSE vs streamable-HTTP**: SSE (`/sse`) is persistent and simpler to debug but can silently drop mid-session. Streamable-HTTP (`/mcp`, POST per tool call, no persistent connection) is more reliable for tool calls. Default to streamable-HTTP for new MCP servers; use SSE only if client compatibility requires it. (confidence: MED, source: multiple projects — conflicting signals, date: 2026-03-09)
- **FastMCP 3.x schema inspection**: `_tool_manager` attribute was removed in FastMCP 3.x. To inspect generated schemas: `tools = await mcp.list_tools(); print(tools[0].to_mcp_tool().inputSchema)`. Don't use internal attributes; use the public MCP protocol methods. (confidence: HIGH, source: FastMCP 3.x migration, date: 2026-03-09)
- **External pricing/booking APIs return transient offers — always cache with TTL**: Any 3rd-party booking API (Amadeus, Stripe, hotel aggregators) returns offers/prices that expire (typically 15-30 min). Cache the full raw offer object after search (keyed by display ID) so downstream steps (pricing confirmation, booking, seat selection) can reference it. Delete from cache on TTL expiry. (confidence: HIGH, source: multiple projects — external API integration, date: 2026-03-11)
- **Graceful fallback with local IDs for external booking APIs**: When an external booking API call fails (sandbox limits, network error), don't propagate the error — generate a local booking record with UUID-based IDs (`uuid4().hex[:8].upper()`), log a warning, and return success. (confidence: HIGH, source: multiple projects — external API integration, date: 2026-03-11)
- **Aisle-gap algorithm for seat type detection is more reliable than column-letter mapping**: Hardcoded lists of aisle columns (`["C", "D", "G", "H"]`) fail for non-standard configs. Instead, represent layout as `["A","B","C","","D","E","F"]` (empty string = aisle gap) then check `columns[i-1]==""` (left of aisle = AISLE) and `columns[i+1]==""` (right of aisle = AISLE). Works for any aircraft config. (confidence: HIGH, source: seat map implementation, date: 2026-03-09)
