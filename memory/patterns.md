# Cross-Project Learned Patterns

Patterns confirmed across multiple projects and sessions. Updated by `/reflect`.

---

## Workflow

- **QA: classify acceptance criteria as automatable vs manual**: After implementation, read the plan's success criteria and split into two buckets: (1) *Automatable* — verify with curl/grep/jq/file check (HTTP status, JSON shape, file existence, env var presence); (2) *Manual-only* — requires human/browser (UI rendering, auth flows, AI output quality, form interactions). Run automatable checks immediately. Write manual-only criteria to a `[task]-qa.md` checklist file so they aren't forgotten. (confidence: HIGH, source: confirmed across multiple projects, date: 2026-03-14)
- **Research > Discuss > Map > Implement**: Never jump to implementation. Establish foundations first — research the domain, discuss with user to align, map the solution, then build. (confidence: HIGH, source: multiple projects, date: 2026-03-08)
- **4-gate plan review — confidence alone is insufficient**: A plan passes review only when all 4 gates are met: (1) confidence >= 96%, (2) User Role Coverage matrix (every role with full call chain + auth guard), (3) Plan Wiring (each major flow written as `Component → api.ts function → HTTP METHOD /path → service.function() → Model.field`), (4) Migration Checklist (every schema change has named migration file + command). Confidence-only review misses unimplemented roles, missing migrations, and broken wiring. Observed failure modes: admin endpoint implemented but customer endpoint missing; migration step omitted from plan; step says "update frontend" without naming file/function. (confidence: HIGH, source: confirmed across multiple projects — 2 separate corrections, date: 2026-03-15)
- **Full-stack field addition order that minimizes rework**: model → schema → service → API route helper → API route endpoint → migration → frontend types → frontend UI. Going frontend-first or migration-first causes rework when the model shape turns out different than expected. (confidence: HIGH, source: confirmed 2× sessions on the same project, date: 2026-03-09)
- **Subagent size threshold for research**: ≥8 files across frontend+backend → use Explore subagent (one-pass comprehensive context). ≤4 specific, known files → use Read/Grep directly (subagent overhead not worth it). (confidence: HIGH, source: multiple projects — 3 separate tasks confirmed, date: 2026-03-09)
- **Verify code state, not plan file status**: Plan files can say "Draft" or "In Progress" while the code is already fully implemented. Always read the actual source files to verify implementation state before starting — avoids re-doing work. (confidence: MED, source: multiple projects — 2 separate tasks, date: 2026-03-09)
- **Multiple `/rplan-review` passes catch layered bug classes**: A single review pass is insufficient. Each pass finds a different category: Pass 1 catches safety/correctness issues (infinite recursion, auth ambiguity, missing guards). Pass 2 catches implementation ambiguity (redirect ownership, internal flag mechanisms, await-vs-fire-and-forget timing). Pass 3 catches logic bugs (JS truthiness traps, missing SQL clauses like RETURNING). When user requests a second review, it is always productive — never skip it as redundant. (confidence: HIGH, source: confirmed across 3 sessions on a multi-tenant SaaS project, date: 2026-03-29)

## Code Quality

- **Never use `transition-all` on interactive cards/toggles**: Use `transition-colors` or list specific properties. `transition-all` animates width/height/shadow changes causing layout jank, especially in grid layouts. (confidence: HIGH, source: multiple projects, date: 2026-03-08)
- **Tailwind `focus:ring-offset-*` adds real box space**: Avoid on elements inside constrained grids/flexbox — it pushes parent containers wider on focus. Use `focus:ring` without offset, or `focus:outline` instead. (confidence: MED, source: multiple projects, date: 2026-03-08)

## Tools

- **Reading PDFs: WebFetch saves binary, use pdftotext**: WebFetch downloads PDFs as binary to a local path but can't extract text. Install poppler (`brew install poppler`) then run `/opt/homebrew/bin/pdftotext file.pdf -` to extract text. `pdftotext` is NOT in default shell PATH. (confidence: HIGH, source: research session, date: 2026-03-09)

## Debugging

- **Empty catch blocks = invisible bugs**: `catch { return; }` or `catch {}` in async init/setup makes it impossible to diagnose which stage fails. Always log `console.warn(err)` at minimum in every catch block, even for "non-critical" features. Real impact: hardware-delegated API (e.g. MediaPipe) failed silently at 3 different stages with no way to distinguish them. (confidence: HIGH, source: multiple projects — 2 sessions, date: 2026-03-08)
- **Browser cache first for "stuck loading" web debugging**: Frontend "stuck loading" with healthy vite process + healthy backend API = almost always a browser cache issue. `Cmd+Shift+R` (hard reload) is the first fix to try before touching any code. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **2-strike rule for CSS/layout bugs**: If 2 CSS fixes don't work, STOP guessing. Trace the full chain: what state changed → what component re-rendered → what DOM mounted/unmounted → what caused the layout shift. The bug is often in a parent component, not the element itself. (confidence: HIGH, source: multiple projects — 5 failed attempts before tracing to parent reflow, date: 2026-03-08)
- **Verify subagent claims before putting them in a plan**: Subagents occasionally misread patterns or flag correct API as bugs. When a subagent reports something as "critical" or "buggy", read the actual code lines before including it in the plan. Examples: LangGraph `ainvoke(None)` flagged as bug (correct API); reviewer subagent flagged RLS as missing without reading the migration SQL — it was already there. **Specific failure mode**: reviewer/research subagents don't automatically read adjacent files (migrations, schemas, config). A CRITICAL security flag from a subagent is only confirmed after checking the actual evidence file yourself. (confidence: HIGH, source: multiple projects — 3 sessions, date: 2026-03-09)
- **Search ALL injection points, not just the obvious one**: When modifying how data is processed, always grep for ALL places that code path is called. Easy to miss fallback paths and leave an optimization half-done. Pattern confirmed 3×: same issue for guidelines injection, RAG config params, and retriever call sites. (confidence: HIGH, source: multiple projects — 3 sessions, date: 2026-03-11)
- **`if x:` truthiness guard silently skips falsy-but-valid values**: Empty string `""`, `0`, and `False` are all falsy but can be valid IDs/values. Use `if x is not None:` when guarding on presence, not `if x:`. Example: `if node_ids and session_id:` skipped detection when `session_id=""`. (confidence: HIGH, source: multiple projects — 2 variants, date: 2026-03-09)
- **`URLSearchParams.size` is unreliable across Node versions**: `.size` getter was added in Node 19 — not available in Node 18 or earlier. Even Node 20 environments (e.g. Docker alpine) can behave unexpectedly. Always use `params.toString()` truthiness (`const qs = params.toString(); url + (qs ? '?' + qs : '')`) instead of `params.size`. (confidence: HIGH, source: confirmed — caused runtime 500, date: 2026-03-14)
- **Restart dev servers after ANY code change before declaring done**: Both Next.js (Turbopack) and Go (`go run .`) require manual restart to pick up new files/routes. Turbopack may not detect newly created page directories — returns 500. Go binary never hot-reloads — new routes return 404 until restart. **BLOCKING**: After implementing backend/frontend changes, always (1) restart affected server, (2) verify the new endpoint/page responds with curl, (3) THEN tell user to test. Kill first: `kill $(lsof -ti :PORT)`. Known triggers: new file created while dev server runs, new route added to Go mux, `npm run build` while Turbopack runs. (confidence: CRITICAL, source: confirmed — 7 occurrences across 4 sessions on a Go + Next.js project, date: 2026-03-14)
- **CORS `ERR_FAILED` + "no headers" = backend crashed before sending response**: When a CORS error shows no response headers (not even a 500), the issue is NOT CORS misconfiguration — it's a backend crash. Starlette's CORSMiddleware doesn't add CORS headers when inner middleware raises an unhandled exception. Diagnosis: (1) OPTIONS preflight succeeds → CORS config is fine; (2) actual POST/GET fails with ERR_FAILED → crash in handler. Fix: find the AttributeError/crash in backend logs, not the CORS config. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **Fix attribute chain errors by reading the class definition first**: When `obj.foo.bar` raises AttributeError, read the class at its definition (not callers) to find the real attribute name. Guessing one level at a time wastes cycles. (confidence: HIGH, source: multiple projects — 2 rounds of guessing before reading class, date: 2026-03-09)

## React Patterns

- **Lucide icon names: verify before use** — compound/descriptive names like `LayoutPanelRight`, `PanelLayoutRight` do not exist. Real names are short: `PanelLeft`, `PanelRight`, `PanelTop`, `PanelBottom`. Verify with: `node -e "const l = require('./node_modules/lucide-react'); console.log(!!l.PanelRight)"`. (confidence: HIGH, source: multiple projects — 2 separate sessions, date: 2026-03-10)
- **Optional `className` for flexible-width components**: When a component has a hardcoded width (e.g. `w-[400px]`), add `className?: string` prop and use `className ?? 'w-[400px] ...'` as the root element's class. Existing consumers are unaffected; callers that need full-width or overlay can override freely. (confidence: MED, source: multiple projects, date: 2026-03-10)
- **Grep ALL usages of any symbol before removing it**: Before deleting a state variable, import, prop, or exported function, grep the ENTIRE file (or codebase) for all references — including setters (`setFoo`), secondary uses of the same import, and downstream consumers. Confirmed causes: `MapPin is not defined` (import removal, 2×), `Search is not defined` (import removal), stale setter crash. Use: `grep -n "symbolName" file.tsx` before any deletion. (confidence: HIGH, source: multiple projects — 6+ occurrences across several projects, date: 2026-03-09)
- **Ref-for-latest-value in async callbacks**: When a callback closed over state will be called asynchronously (WS `onmessage`, MediaRecorder `onstop`, `setTimeout`, audio `onended`), use a ref (`valueRef.current = value`) synced in the render body so the callback always reads the current value. State is stale inside closures; refs are not. (confidence: HIGH, source: multiple projects — voice + WebSocket handlers, date: 2026-03-09)
- **Recursive async hook restart needs a function ref**: For hooks that restart themselves (continuous recording, polling loops), store `startFnRef.current = startFn` after `useCallback`, then call `startFnRef.current()` inside async callbacks (`onstop`, `onended`). Calling the function directly from inside its own closure causes a stale reference to the initial version. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **Two restart sites for continuous audio/voice loops**: Auto-restart after a successful round goes in `audio.onended`. Auto-restart after an empty/silent round must go in the `onstop` handler itself (with a shorter delay). Missing either site silently kills the loop. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **`useSearchParams()` requires `<Suspense>` boundary in Next.js App Router**: Components using `useSearchParams()` must be wrapped in `<Suspense>` — build fails at static generation without it. Split into a client component (with `useSearchParams`) imported by a server component that wraps it in `<Suspense fallback={...}>`. (confidence: HIGH, source: confirmed across 2 projects, date: 2026-03-14)

## Next.js App Router

- **Same-segment navigation does NOT remount client components**: Navigating between `/content/movie-a` → `/content/movie-b` (same `[slug]` route) keeps the component mounted. `params.slug` changes in-place; all `useState` persists. Any state that should reset between "pages" (e.g. resume position, scroll position, fetched data) must be explicitly reset via a `useEffect` that depends on the route param. (confidence: MED, source: content streaming project — resume playback bug, date: 2026-03-19)

## React / Frontend Architecture

- **Three-way render gate for async-resolved content**: When a component renders differently based on async state, use three branches: `null → Skeleton`, `resolved + data → Component`, `resolved + no-data → Fallback`. Never use a flat AND gate (`resolved && data ? <X> : <Fallback>`) — this incorrectly shows the fallback during loading. Template: `{state === null ? <Skeleton /> : data ? <Component /> : <Fallback />}`. (confidence: MED, source: content streaming project — resume playback, date: 2026-03-19)
- **Auth `isLoading` race — `isAuthenticated` starts `false` during token refresh**: Any `useEffect` that branches on `isAuthenticated` must also gate on `!isLoading` (or `!authLoading`). On mount, `isAuthenticated=false` AND `isLoading=true` — this is "unknown", not "logged out". If the effect fires before `refreshToken()` resolves, it executes the anonymous branch for every authenticated user. Guard: `if (isLoading) return;` as the first line in any auth-dependent effect. (confidence: MED, source: content streaming project — auth race during playback resume, date: 2026-03-19)
- **Callback/render props to avoid cross-feature imports**: When Feature A needs to render or interact with Feature B, use render props (`actionSlot?: React.ReactNode`) or callback props (`onTimeUpdate?: (currentTime, duration) => void`) instead of direct imports. The parent in `app/` orchestrates — it passes Feature B's component via prop to Feature A, which renders it without importing. Keeps features decoupled and independently testable. (confidence: HIGH, source: confirmed — 3 occurrences in one project (watchlist button, video player, content card), date: 2026-03-19)

## AI / LLM Integration

- **Named semantic presets > raw LLM-generated numerical arrays**: When an LLM needs to output precise numerical values (curve control points, coordinates, timing offsets), define a small set of named presets in the prompt and map them to exact values in code. LLMs describe semantics reliably; they generate inaccurate precise floats. Examples: curve presets ("s_curve", "film_fade"), animation easing ("ease_in", "spring"), layout modes. (confidence: MED, source: iOS photo editing app — AI color grading feature, date: 2026-03-12)
- **Domain vocabulary in system prompts improves AI output calibration**: Include professional terminology (film stock names, design pattern names, grading technique names) in system prompts. LLMs reason better when they can anchor to named concepts they were trained on vs. purely numerical ranges. Example: "Kodak Portra: lifted blacks, warm shadows" produces more accurate color grading output than "slightly brighter shadows". (confidence: MED, source: iOS photo editing app — AI color grading feature, date: 2026-03-12)
- **Calibration tables prevent LLM value extremism**: LLMs default to dramatic values when asked to replicate visual styles. Add a "subtle/moderate/strong" table for each parameter type (e.g. HSL saturation: ±0.1 subtle, ±0.25 moderate, ±0.5 strong) and an "interaction rules" section (don't stack contrast slider + s_curve). This makes AI output conservative and stackable rather than over-processed. (confidence: MED, source: iOS photo editing app — AI prompt enhancement, date: 2026-03-12)
- **Keep prompt JSON schema in sync with parser**: When an LLM is asked to return structured JSON, every field in the schema must have a corresponding parser entry. Fields in the prompt but not in the parser are silently discarded — no error, no warning. Mitigation: write the parser and the prompt schema at the same time; grep the schema keys against the parser when reviewing. (confidence: MED, source: iOS photo editing app — AI color grading feature, date: 2026-03-12)

## iOS / SwiftUI

- **`@ViewBuilder` forbids local `func` declarations**: Declaring a `func` inside a `@ViewBuilder` closure (GeometryReader body, group body, etc.) causes "Closure containing a declaration cannot be used with result builder". Inline the calculation or extract it to a computed property / struct method. (confidence: HIGH, source: iOS photo editing app — curve view fix, date: 2026-03-12)
- **SwiftUI `DragGesture` Y-axis must be flipped for math/art coordinates**: SwiftUI y+ is down; standard math, color wheels, and image coordinates use y+ = up. Always apply `dy = -(value.location.y - center)` before storing. Missing this makes dragging up move the control point down. (confidence: HIGH, source: iOS photo editing app — color wheel view, date: 2026-03-12)
- **SwiftUI View static methods are implicitly `@MainActor`**: Any `static func` defined on a `View` struct is MainActor-isolated and cannot be called from `Task.detached` or `nonisolated` context. Fix: mark as `nonisolated static func`. Applies to computed-image helpers, histogram computation, LUT builders called from background tasks. (confidence: HIGH, source: iOS photo editing app — Swift 6 actor isolation error, date: 2026-03-12)
- **`WritableKeyPath` as panel binding factory param**: Pass `WritableKeyPath<Model, Value>` to a helper that creates a `Binding<Value>` via `Binding(get: { model[keyPath: kp] }, set: { ... })`. Lets a single factory method produce bindings for lift/gamma/gain without repeating the binding construction code. (confidence: MED, source: iOS photo editing app — color grade panel, date: 2026-03-12)
- **Inset curve/canvas by `pointRadius` on all sides**: Edge control points at (0,0) and (1,1) are clipped if the drawing rect matches the frame. Apply uniform `pad = pointRadius` inset: map normalized x,y to `pad + x*(width - 2*pad)`, and invert the same formula for drag hit detection. (confidence: HIGH, source: iOS photo editing app — curve view edge clipping fix, date: 2026-03-12)
- **Multiple `.fileImporter` / `.sheet` modifiers on the same SwiftUI view → silent failure**: SwiftUI only processes one modal per view. Stacking 2+ `.fileImporter` or mixing `.sheet` + `.fileImporter` on the same parent causes some/all pickers to silently not appear. Fix: attach each modifier to a different child view (e.g., one on HStack, one on ScrollView). (confidence: HIGH, source: iOS photo editing app — file import bug, date: 2026-03-12)
- **`DragGesture.value.translation` is cumulative, not per-tick delta**: `value.translation` accumulates from gesture start — applying it as a delta each tick causes accelerating drift. Fix: capture `dragStartValue` on the first `.onChanged` tick, then always compute as `startValue + totalTranslation`. (confidence: HIGH, source: iOS photo editing app — crop rect drag bug, date: 2026-03-12)
- **SwiftUI `ScrollView` children overlap at origin without `VStack` wrapper**: `ScrollView { view1; view2 }` positions all children at origin — they stack on top of each other. Always wrap `ScrollView` content in `VStack(spacing: 0)` when multiple siblings are present. (confidence: HIGH, source: iOS photo editing app — UI polish fix, date: 2026-03-12)
- **`CADisplayLink` is required for per-frame animation on `MTKView`**: `UIView.animate` only animates UIView-backed properties (frame, alpha, transform). Custom Swift properties on `MTKView` don't animate — they snap immediately. Use `CADisplayLink` + `setNeedsDisplay()` per frame for smooth custom-property interpolation on Metal views. (confidence: HIGH, source: iOS photo editing app — Metal view animation fix, date: 2026-03-12)
- **Reliable square photo grid cell**: `Color.clear.aspectRatio(1, contentMode: .fit).overlay { Image(...).resizable().scaledToFill() }.clipped()` — `Color.clear` sets the size, `aspectRatio` makes it square, overlay fills it, `.clipped()` on the outer container prevents overflow. `.clipped()` must be OUTSIDE the overlay, not inside it. (confidence: HIGH, source: iOS photo editing app — grid layout fix, date: 2026-03-12)
- **Custom `init` inside Swift `struct` body suppresses compiler-synthesized memberwise init**: All call sites using the default `.init(field:)` syntax break. Move custom inits to an `extension` of the struct — this preserves the synthesized memberwise init for existing callers. (confidence: HIGH, source: iOS photo editing app — struct init fix, date: 2026-03-12)

## iOS / Core Image

- **`CITemperatureAndTint` neutral/targetNeutral semantics**: `neutral` = what the filter treats as the *current* image's color temperature; `targetNeutral` = what you want to shift toward. Swapping them inverts the effect (warm → cool, cool → warm). Correct: `neutral = (6500, 0)` (assume daylight), `targetNeutral = (desiredTemp, tint)`. (confidence: HIGH, source: iOS photo editing app — temperature filter bug, date: 2026-03-12)
- **`xcodegen generate` required after creating new Swift files**: XcodeGen auto-discovers Swift files via `sources: path:` glob, but `project.pbxproj` reflects the last `xcodegen generate` run. New files created after that run cause "cannot find X in scope" — even if the file is on disk and syntactically valid. Run `xcodegen generate` immediately after creating any new `.swift` file. (confidence: HIGH, source: confirmed — 2 sessions, date: 2026-03-12)
- **`CIHighlightShadowAdjust.highlightAmount` documented range is 0.0–1.0**: Don't use `1.0 + userValue` which produces 0–2. Positive highlight boost beyond 1.0 is undefined behavior. Clamp: `min(1.0, max(0.0, 1.0 + userValue))`. Shadow amount is -1.0 to 1.0 and maps directly. (confidence: HIGH, source: iOS photo editing app — highlights bug, date: 2026-03-12)
- **CIImage/CIFilter pipeline is already 32-bit float**: CIFilter chains and CIContext internal working space operate at full float precision. Bit depth loss only happens at the *output* stage. To upgrade to 16-bit: pass `format: .RGBA16` to `CIContext.tiffRepresentation()` / `heifRepresentation()`. For 8-bit use `.RGBA8`. No changes to the processing pipeline needed — only the final render call. (confidence: HIGH, source: iOS photo editing app — bit depth feature, date: 2026-03-12)
- **`CIGaussianBlur` expands the image extent**: After applying `CIGaussianBlur`, the output image is larger than the input (by the blur radius on each side). Always chain `.cropped(to: inputImage.extent)` immediately after to restore original bounds. Skipping this causes downstream filters to render a larger canvas with transparent edges. (confidence: HIGH, source: iOS photo editing app — CIFilter pipeline, date: 2026-03-12)
- **MTKView `rgba16Float` pixel format enables EDR preview on iPhone 12+**: Set `colorPixelFormat = .rgba16Float` (instead of `.bgra8Unorm_srgb`) in MTKView setup for 16-bit float display with Extended Dynamic Range support. The CIContext/CIRenderDestination path handles the pixel format transparently — no shader changes needed. (confidence: MED, source: iOS photo editing app — bit depth feature, date: 2026-03-12)
- **`[[stitchable]]` CIKernel in regular `.metal` files (iOS 15+)**: Simpler than `extern "C"` `.ci.metal` — no custom build rules, just `MTLLINKER_FLAGS: "-framework CoreImage"`. Uses `#include <CoreImage/CoreImage.h>`, `coreimage::sample_t` input, returns `float4`. Coexists with regular compute shaders in `default.metallib`. Load via `CIColorKernel(functionName:fromMetalLibraryData:)`. (confidence: HIGH, source: iOS photo editing app — filmic exposure kernel, date: 2026-03-13)
- **Display P3 luminance weights ≠ sRGB**: P3 = `(0.2290, 0.6917, 0.0793)`, sRGB = `(0.2126, 0.7152, 0.0722)`. Use P3 weights when `CIContext.workingColorSpace` is Display P3. Difference is small but matters for accurate luminance computation in tone mapping and desaturation. (confidence: HIGH, source: iOS photo editing app — filmic exposure, date: 2026-03-13)
- **ACES tone mapping has hue shifts — avoid for photo editing**: ACES (Narkowicz fit or RRT+ODT) shifts blues→purple and reds→orange at high intensities. Use AgX or log-logistic sigmoid instead for photo editing where hue accuracy matters. Log-logistic: `f(x) = x^c / (x^c + sigma^c)` with `sigma = midgrey * pow((1-midgrey)/midgrey, 1/c)` preserves middle grey at any contrast. (confidence: HIGH, source: iOS photo editing app — filmic exposure research, date: 2026-03-13)

## Audio / Voice / AI

- **OpenAI hosted whisper-1 has no tunable server params**: `vad_filter`, `condition_on_previous_text`, `compression_ratio_threshold`, `no_speech_threshold` are only available in self-hosted Whisper/faster-whisper. When using the OpenAI API, all anti-hallucination defense must be client-side. (confidence: HIGH, source: deep research + implementation, date: 2026-03-09)
- **Never use Whisper `initial_prompt` for continuous voice chat**: Research (OpenAI community + GitHub issues) shows `initial_prompt` causes ~80% fully-hallucinated looping output in continuous contexts. Use hallucination blocklist + VAD + echo cancellation instead. (confidence: HIGH, source: research + external sources, date: 2026-03-09)
- **7-layer client-side anti-hallucination stack for Whisper**: (1) VAD (Silero/@ricky0123/vad-web), (2) echoCancellation+noiseSuppression on getUserMedia, (3) speechDetected RMS threshold flag, (4) hallucination string blocklist (60+ strings, 12+ languages), (5) repetition/loop detector (word count + unique ratio), (6) min cumulative speech duration, (7) consecutive-silence bail-out (3 strikes → pause). First two give the highest ROI. (confidence: HIGH, source: research + implementation, date: 2026-03-09)

## Go

- **`go test ./...` is the real verification gate, not `go build ./...`**: `go build` compiles production code but skips test files entirely. When an interface gains new methods or a service signature changes, `go build ./cmd/server` still passes — but `go test ./...` fails because mock structs and test call sites are stale. Always run `go test` (not just `go build`) after changing interfaces, service constructors, or exported function signatures. (confidence: HIGH, source: confirmed — 4 occurrences across 2 projects, date: 2026-03-19)
- **Go HTTP router: register static routes BEFORE parameterized routes**: In Gin (radix tree) and Go ServeMux, registering `/:slug` or `/{slug}` before `/trending` causes the parameterized route to catch the static path. Despite docs claiming static routes take priority, insertion order determines matching in practice. Fix: split route registration so static routes register first, parameterized routes last. (confidence: HIGH, source: confirmed across 2 projects (Gin radix tree + Go ServeMux), date: 2026-03-19)
- **Go DTO struct fields must have explicit `json:"snake_case"` tags**: `encoding/json` defaults to PascalCase field names when no tag is present (e.g. `ActiveUsers` → `{"ActiveUsers":100}`). API clients (TypeScript, mobile, etc.) almost always expect snake_case. Always add tags to every struct field used in HTTP responses. Missing tags produce silent data loss — the struct marshals successfully but the client reads `undefined`. Caught repeatedly only in adversarial plan review, not in code review. (confidence: HIGH, source: caught in adversarial plan review — 4th pass, date: 2026-03-19)
- **pgx `rows.Err()` must be called after every `for rows.Next()` loop**: When the loop terminates due to a network or decode error, `rows.Next()` returns `false` normally — the error is only surfaced via `rows.Err()`. Omitting the check silently returns a partial result with HTTP 200. Fix: always add `if err := rows.Err(); err != nil { return nil, fmt.Errorf("iterate X rows: %w", err) }` after the loop. (confidence: HIGH, source: pre-existing bug caught in code review, date: 2026-03-30)
- **Gin context key type assertion panics for optional-auth endpoints**: `val.(string)` panics when the context key is not set (nil interface{}). `RequireAuth` always sets the key so authenticated handlers are safe — but NEVER copy that pattern for optional-auth handlers. Use the ok-idiom: `if val, exists := c.Get(key); exists { if str, ok := val.(string); ok { ... } }`. Direct assertion on an unset key = guaranteed panic on anonymous requests. (confidence: HIGH, source: confirmed — 2 occurrences, second time in optional-auth variant, date: 2026-03-19)
- **Gin radix tree: ALL parameterized routes on the same path segment must use the SAME wildcard name**: `/:slug/comments` and `/:contentId/view` on the same RouterGroup panics at startup — Gin requires one wildcard name per path segment. When multiple modules register sub-routes under a shared group, standardize on one param name (`:slug`) across all modules. This is a build-time panic, not a runtime error — `go build` passes but the server crashes on startup. Always start the server after route changes to verify. (confidence: HIGH, source: confirmed — 3 Gin routing issues across multiple sprints, date: 2026-03-19)

## Architecture

- **Global-first design**: Build frameworks in `~/.claude/` (applies everywhere), then scaffold project-specific layers via `/init-env`. Avoid project-only solutions when the pattern is reusable. (confidence: HIGH, source: multiple projects, date: 2026-03-08)
- **PostgreSQL CHECK constraint modification = DROP + re-ADD**: CHECK constraints cannot be ALTERed in-place. To add a new allowed value: `ALTER TABLE t DROP CONSTRAINT t_col_check; ALTER TABLE t ADD CONSTRAINT t_col_check CHECK (col IN ('old1', 'old2', 'new'));`. Same for removing values. Always pair with a down migration that reverts the constraint. (confidence: HIGH, source: confirmed across 3 sessions, date: 2026-03-14)
- **3-layer "one active per user" enforcement**: Never rely on just one layer. Enforce at: (1) application logic (check in handler before insert), (2) DB partial unique index (`CREATE UNIQUE INDEX ... WHERE status IN ('pending','approved')`), (3) frontend pre-fetch + hide CTA proactively. Each layer catches a different failure mode: app logic catches normal flow; DB index catches race conditions and direct API calls; frontend hides the affordance so users never hit the constraint at all. (confidence: HIGH, source: confirmed, date: 2026-03-14)
- **Partial unique index for "one active per user" with history**: `CREATE UNIQUE INDEX idx_foo_user_active ON foo(user_id) WHERE status IN ('pending','approved')`. Enforces one active record per user while allowing unlimited rejected/cancelled/historical records. Much more flexible than a simple UNIQUE constraint on `(user_id)`. (confidence: HIGH, source: confirmed, date: 2026-03-14)
- **setLive/commitLive split for editor undo history**: Any reactive editor with sliders + undo must separate continuous input from history commits. `setLive(params)` during drag = live preview, no history entry. `commitLive()` on drag end = one undo step. `update(params)` for discrete actions (preset apply, AI apply, reset button) = immediate history entry. An executable `/foo` command requires `~/.claude/skills/foo/SKILL.md` — the subdirectory signals it's a slash command. These two look similar but behave completely differently; confusing them means the command silently never appears. (confidence: HIGH, source: discovered when a custom skill wasn't invocable, date: 2026-03-31)
- **Project skill overrides global skill via `.claude/skills/`**: `<project>/.claude/skills/<name>/SKILL.md` takes precedence over `~/.claude/skills/<name>/SKILL.md`. Use this for project-specific domain expert configuration — keep the global version language-agnostic, scaffold the project override with `/init-env`. Enables one workflow to serve all projects without forking the global file. (confidence: HIGH, source: confirmed when overriding rplan-review for a Go/Next.js/PostgreSQL project, date: 2026-03-31)
- **Parallel domain expert agents > sequential generalist probe loop for plan review**: A single generalist asking probe questions sequentially requires 5-10 manual prompt rounds to cover all risk areas. Launching domain-specific agents in parallel (Backend, Frontend, DB/Security, Product) covers all blind spots in one pass — each agent knows its domain's failure modes and non-negotiable blockers. The synthesis step deduplicates and scores confidence automatically. Apply this pattern to any review or audit skill that currently uses a sequential loop. (confidence: HIGH, source: rplan-review redesign — extends "confidence-driven loops" pattern, date: 2026-03-31)
- **QA skills must be criteria-driven, not tool-driven**: A QA skill that runs `go test`, `npm test`, and `playwright test` generically fails silently when any tool is missing or not set up — it ends with "install X" instead of useful signal. The correct design: read the plan's Success Criteria, classify each criterion by type (API/test/file/UI), and run the best available command for that type. `curl` covers API criteria without a test framework; `go test -run [Name]` covers service criteria; file checks cover migration criteria. Generic tool commands are a fallback, not the primary driver. (confidence: HIGH, source: /qa failure mode — caught in practice, date: 2026-03-31)
- **Review skills must rewrite vague criteria, not just flag them**: A review phase that flags "acceptance criteria too vague" as a blocker forces the user to fix manually — this is the same friction being automated away. The correct design: rewrite each vague criterion in-place using the plan's wiring (Given/When/Then + exact test command + expected outcome), edit the plan file, and proceed. By the time implementation starts, every criterion must be machine-executable. "Flag and block" is half the job; rewriting completes it. (confidence: HIGH, source: rplan-review Phase 1.5 design, date: 2026-03-31)
- **MANUAL and BLOCKED are not SKIP**: In QA and review skills, a criterion that can't be auto-verified still needs a result. `MANUAL` = UI interaction required — list the exact browser steps. `BLOCKED` = dependency missing (server down, token needed) — state exactly how to unblock. `SKIP` means "we gave up" and produces a false green signal. Every criterion must have a verdict; none may be silently omitted. (confidence: HIGH, source: /qa design correction, date: 2026-03-31)

## Python Async

- **`asyncio.to_thread()` / `run_in_executor()` for any synchronous call in async context**: Never call synchronous operations directly in an async handler — blocks the event loop for all concurrent requests. Rule: **CPU-bound sync (ML inference, compression)** → `await asyncio.to_thread(fn, *args)`. **I/O-bound sync SDK (boto3, stripe, any sync HTTP client)** → `await loop.run_in_executor(None, partial(fn, **kwargs))`. For startup preloading, use `loop.run_in_executor(None, preload_fn)` in the lifespan handler to avoid cold-start delay. (confidence: HIGH, source: multiple projects — 2 different contexts confirmed, date: 2026-03-11)
- **`except Exception` misses `CancelledError` in Python 3.8+**: `CancelledError` is `BaseException`, not `Exception`. In startup/lifespan safety nets and reconnect loops, always use `except BaseException` to prevent silent crash propagation. Real production impact: FastAPI backend crashed at startup every time an external service was unreachable. (confidence: HIGH, source: multiple projects — lifespan + reconnect patterns, date: 2026-03-10)
- **anyio cancel scope must be entered/exited in the same asyncio Task**: When `anyio.create_task_group()` is used inside an async context manager, entering via `__aenter__()` in one task and exiting in another raises `RuntimeError: Attempted to exit cancel scope in a different task than it was entered in`. Fix: run each anyio-dependent operation in its own `asyncio.create_task()`. (confidence: HIGH, source: multiple projects — MCP/SSE client pattern, date: 2026-03-10)

## MCP Servers

- **MCP servers must start BEFORE the backend for auto-reconnect**: `reconnect_all` runs once at startup. If any MCP server is down at that moment, its tools are silently missing at runtime (tool returns "not found"). Correct start order: MCP servers first, then backend. If order was wrong: restart backend or reconnect via UI. (confidence: HIGH, source: multiple projects — repeated across 2 sessions, date: 2026-03-10)
- **`list[dict]` params generate `additionalProperties:true` schema → LLM skips them**: FastMCP infers JSON Schema from function type hints. `list[dict]` yields `{"items": {}, "additionalProperties": true}` — LLM treats it as optional freeform and often omits it entirely. Use Pydantic models so FastMCP generates a full named schema with required fields the LLM must fill. (confidence: HIGH, source: multiple projects — tool param always missing, date: 2026-03-09)
- **LLM constructs IDs from known fields instead of using returned IDs**: When search results return opaque IDs, LLM in subsequent turns often reconstructs a plausible-looking ID rather than copying the actual returned value. Two defenses: (1) make IDs human-readable with embedded context, (2) add fuzzy fallback lookup on the server side. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **FastMCP transport options — SSE vs streamable-HTTP**: SSE (`/sse`) is persistent and simpler to debug but can silently drop mid-session. Streamable-HTTP (`/mcp`, POST per tool call, no persistent connection) is more reliable for tool calls. Default to streamable-HTTP for new MCP servers; use SSE only if client compatibility requires it. (confidence: MED, source: multiple projects — conflicting signals, date: 2026-03-09)
- **FastMCP 3.x schema inspection**: `_tool_manager` attribute was removed in FastMCP 3.x. To inspect generated schemas: `tools = await mcp.list_tools(); print(tools[0].to_mcp_tool().inputSchema)`. Don't use internal attributes; use the public MCP protocol methods. (confidence: HIGH, source: FastMCP 3.x migration, date: 2026-03-09)
- **External pricing/booking APIs return transient offers — always cache with TTL**: Any 3rd-party booking API (Amadeus, Stripe, hotel aggregators) returns offers/prices that expire (typically 15-30 min). Cache the full raw offer object after search (keyed by display ID) so downstream steps (pricing confirmation, booking, seat selection) can reference it. Delete from cache on TTL expiry. (confidence: HIGH, source: multiple projects — external API integration, date: 2026-03-11)
- **Graceful fallback with local IDs for external booking APIs**: When an external booking API call fails (sandbox limits, network error), don't propagate the error — generate a local booking record with UUID-based IDs (`uuid4().hex[:8].upper()`), log a warning, and return success. (confidence: HIGH, source: multiple projects — external API integration, date: 2026-03-11)
- **Aisle-gap algorithm for seat type detection is more reliable than column-letter mapping**: Hardcoded lists of aisle columns (`["C", "D", "G", "H"]`) fail for non-standard configs. Instead, represent layout as `["A","B","C","","D","E","F"]` (empty string = aisle gap) then check `columns[i-1]==""` (left of aisle = AISLE) and `columns[i+1]==""` (right of aisle = AISLE). Works for any aircraft config. (confidence: HIGH, source: seat map implementation, date: 2026-03-09)
