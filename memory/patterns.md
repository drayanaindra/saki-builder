## Workflow

- **QA: classify acceptance criteria as automatable vs manual**: After implementation, read the plan's success criteria and split into two buckets: (1) *Automatable* — verify with curl/grep/jq/file check (HTTP status, JSON shape, file existence, env var presence); (2) *Manual-only* — requires human/browser (UI rendering, auth flows, AI output quality, form interactions). Run automatable checks immediately. Write manual-only criteria to a `[task]-qa.md` checklist file so they aren't forgotten. (confidence: HIGH, source: confirmed across multiple projects, date: 2026-03-14)
- **Research > Discuss > Map > Implement**: Never jump to implementation. Establish foundations first — research the domain, discuss with user to align, map the solution, then build. (confidence: HIGH, source: multiple projects, date: 2026-03-08)
- **4-gate plan review — confidence alone is insufficient**: A plan passes review only when all 4 gates are met: (1) confidence >= 96%, (2) User Role Coverage matrix (every role with full call chain + auth guard), (3) Plan Wiring (each major flow written as `Component → api.ts function → HTTP METHOD /path → service.function() → Model.field`), (4) Migration Checklist (every schema change has named migration file + command). Confidence-only review misses unimplemented roles, missing migrations, and broken wiring. Observed failure modes: admin endpoint implemented but customer endpoint missing; migration step omitted from plan; step says "update frontend" without naming file/function. (confidence: HIGH, source: confirmed across multiple projects — 2 separate corrections, date: 2026-03-15)
- **Full-stack field addition order that minimizes rework**: model → schema → service → API route helper → API route endpoint → migration → frontend types → frontend UI. Going frontend-first or migration-first causes rework when the model shape turns out different than expected. (confidence: HIGH, source: confirmed 2× sessions on the same project, date: 2026-03-09)
- **Subagent size threshold for research**: ≥8 files across frontend+backend → use Explore subagent (one-pass comprehensive context). ≤4 specific, known files → use Read/Grep directly (subagent overhead not worth it). (confidence: HIGH, source: multiple projects — 3 separate tasks confirmed, date: 2026-03-09)
- **Verify code state, not plan file status**: Plan files can say "Draft" or "In Progress" while the code is already fully implemented. Always read the actual source files to verify implementation state before starting — avoids re-doing work. (confidence: MED, source: multiple projects — 2 separate tasks, date: 2026-03-09)
- **Multiple `/rplan-review` passes catch layered bug classes**: A single review pass is insufficient. Each pass finds a different category: Pass 1 catches safety/correctness issues (infinite recursion, auth ambiguity, missing guards). Pass 2 catches implementation ambiguity (redirect ownership, internal flag mechanisms, await-vs-fire-and-forget timing). Pass 3 catches logic bugs (JS truthiness traps, missing SQL clauses like RETURNING). When user requests a second review, it is always productive — never skip it as redundant. (confidence: HIGH, source: confirmed across 3 sessions on a multi-tenant SaaS project, date: 2026-03-29)
- **`/rplan-review` score trajectory is itself a convergence signal**: Track the score across rounds. Round-1 score X% → round-2 score Y% with `Y > X` AND fewer/lower-level blockers = converging, ship. `Y ≈ X` AND new blockers at the same level = recut scope, do not run round 3. Real example: 30% → 56% → 73% → 96% across 4 rounds = converged via real fixes; if round 3 had been 56%-stuck-with-same-volume-of-blockers, the right call would have been recut at that point, not round 4. (confidence: HIGH, source: confirmed across multiple projects, date: 2026-05-03)
- **Senior-PM peer review BEFORE shipping when scope fights PRD appetite**: When a plan exceeds its PRD-stated appetite (e.g. PRD §6 says "~4 tasks, recut threshold at 6" but plan is 12), spawn a `senior-pm` subagent with explicit pressure-test questions ("is this cut load-bearing?", "what cuts would you reverse?", "what triggers the deferred phases?") — not "review my plan". Returns reverses on over-aggressive cuts AND pushes correct deferrals. Highest-leverage PM intervention available. (confidence: HIGH, source: confirmed across multiple projects, date: 2026-05-03)
- **Recut > fix-then-fix when blockers accumulate across review rounds**: When `/rplan-review` rounds 1+2 surface 17+ cumulative blockers and the plan is N× over PRD appetite, the load-bearing problem is scope, not implementation gaps. The right move is recut into trigger-gated phases (B → B1+B2+B3 with objective signals like "first dup-row logged", "outcome 5.1 <70%"), not deeper revisions of the same plan. Each revision adds drift faster than it removes blockers. (confidence: HIGH, source: confirmed across multiple projects, date: 2026-05-03)
- **Phase-gate triggers tied to objective signals prevent perpetual deferral**: When deferring scope to "B2 / B3 / later", define each phase's trigger as a measurable signal in production logs/queries (e.g. "B2 ships when first dup-seller row logged OR ≥3 concurrent admins" / "Slice C ships when cohort resubmit-rate <50% within 14 days"). Better than calendar-based ("ship in 2 weeks") or vague-volume ("when needed") thresholds — the trigger fires automatically when the underlying problem appears. (confidence: HIGH, source: confirmed across multiple projects, date: 2026-05-03)
- **Operational owner pin in plan No-Gos as dashboard substitute**: At MVP scale, replace "build a metrics dashboard" with `Owner: @name. Cadence: weekly. SQL snippet: <queries>`. Cheaper than a dashboard, tighter than "monitor somehow"; PRD kill-criterion provides the hard backstop. Only escalate to dashboard when volume justifies (≥2 reviewers, weekly throughput pressure). (confidence: HIGH, source: 1 project, but pattern is generic, date: 2026-05-03)
- **Don't fix unrelated infra mid-PRD — document the workaround, apply per-instance**: When you discover a known infra bug (test conftest event-loop mismatch, broken venv symlinks, schema drift) while starting a new PRD's first slice, the cost of detouring to fix it is 1+ days plus its own ripple-fix tail in unrelated files. The right move: document the workaround in CLAUDE.md (or a `patterns-<topic>.md`) ONCE, then apply the per-instance pattern in every new file across the PRD. A multi-slice PRD that uses the workaround verbatim 8 times costs less than the "fix the infra" side-quest. Trap signal: "we should really fix this conftest thing" — that's exactly when to add it to CLAUDE.md and keep moving. (confidence: HIGH, source: confirmed across 3 sessions on 1 project, date: 2026-05-11)
- **Registry sentinel test design: pick a never-registered key on the first test, not a real future name**: Registry dispatch tables (carrier → client, intent → handler, payment-method → gateway, mime-type → parser) accumulate entries over time. The "unsupported-key returns failure" test gets edited every time a new entry joins IF the test used a real next-up name as its placeholder. Pick a sentinel that's intentionally never going to be a real registered key (`"unknown_carrier"`, `"__unused__"`, `"sentinel_unregistered"`) on the FIRST registry test. Saves a one-line edit on every subsequent expansion — and more importantly, removes a recurring source of "did I forget to update the sentinel test?" mistakes in PRs that add registry entries. (confidence: HIGH, source: 1 project but confirmed 3× via ripple-fix pain across slices, date: 2026-05-11)

## Code Quality

- **Vite 8 (rolldown) requires `import type` for all MUI type re-exports**: Vite 8 switched to rolldown bundler. Combined `import X, { XProps } from '@mui/material/X'` syntax causes `[MISSING_EXPORT]` build errors for any type-only export from MUI subpath imports. Fix: split into `import X from '@mui/material/X'` + `import type { XProps } from '@mui/material/X'`. Also applies to `SxProps`, `Theme` from `@mui/material/styles`. This is a Vite 8 / rolldown issue only — Vite 5 worked fine. (confidence: HIGH, source: ANA design system build, date: 2026-04-14)
- **MUI v5 + npm = pin icon version explicitly**: `npm install @mui/icons-material` auto-resolves to v9 even when `@mui/material` is v5, causing icon export path incompatibilities. Always pin: `npm install @mui/icons-material@5`. (confidence: HIGH, source: ANA design system build, date: 2026-04-14)
- **Never use `transition-all` on interactive cards/toggles**: Use `transition-colors` or list specific properties. `transition-all` animates width/height/shadow changes causing layout jank, especially in grid layouts. (confidence: HIGH, source: multiple projects, date: 2026-03-08)
- **Tailwind `focus:ring-offset-*` adds real box space**: Avoid on elements inside constrained grids/flexbox — it pushes parent containers wider on focus. Use `focus:ring` without offset, or `focus:outline` instead. (confidence: MED, source: multiple projects, date: 2026-03-08)
- **`html.escape()` user-controlled strings before HTML interpolation**: Any user-controlled or admin-authored string interpolated into f-string HTML (email templates, server-side renders, debug pages) needs `html.escape(s)` first. Modern webmail strips `<script>` so this is rarely full XSS, but it IS unwanted HTML reflection — `<a>` injection, `<img onerror=>` payloads, broken layout. Especially dangerous for fields populated by users (full_name, listing_title, reject_reason). Same rule for any string going into HTML attribute context (use `quoteattr` semantics). (confidence: HIGH, source: 1 project + multi-domain rule, date: 2026-05-03)
- **`getComputedStyle` > screenshots for visual-parity / refactor verification**: When verifying a CSS refactor (especially one that drops style declarations on an outer wrapper), assert with `getComputedStyle(el).getPropertyValue('background-color')` etc. — NOT screenshots. Cream-on-white bg, dark-brown vs pure-black text, 13px vs 16px are near-indistinguishable in PNGs at typical zoom; computed-style strings are exact. Screenshots are supplementary, not load-bearing. Before deleting an outer-wrapper style declaration, grep `body`/`global.css` to check whether the property is declared at root — children typically inherit from `body`, which falls back to browser defaults (white bg, black text, 16px) if not set. (confidence: HIGH, source: confirmed 2× on same project, date: 2026-05-08 → 2026-05-09)

## Tools

- **Reading PDFs: WebFetch saves binary, use pdftotext**: WebFetch downloads PDFs as binary to a local path but can't extract text. Install poppler (`brew install poppler`) then run `/opt/homebrew/bin/pdftotext file.pdf -` to extract text. `pdftotext` is NOT in default shell PATH. (confidence: HIGH, source: research session, date: 2026-03-09)

## Debugging

- **Empty catch blocks = invisible bugs**: `catch { return; }` or `catch {}` in async init/setup makes it impossible to diagnose which stage fails. Always log `console.warn(err)` at minimum in every catch block, even for "non-critical" features. Real impact: hardware-delegated API (e.g. MediaPipe) failed silently at 3 different stages with no way to distinguish them. (confidence: HIGH, source: multiple projects — 2 sessions, date: 2026-03-08)
- **Browser cache first for "stuck loading" web debugging**: Frontend "stuck loading" with healthy vite process + healthy backend API = almost always a browser cache issue. `Cmd+Shift+R` (hard reload) is the first fix to try before touching any code. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **2-strike rule for CSS/layout bugs**: If 2 CSS fixes don't work, STOP guessing. Trace the full chain: what state changed → what component re-rendered → what DOM mounted/unmounted → what caused the layout shift. The bug is often in a parent component, not the element itself. (confidence: HIGH, source: multiple projects — 5 failed attempts before tracing to parent reflow, date: 2026-03-08)
- **Verify subagent claims before putting them in a plan**: Subagents occasionally misread patterns or flag correct API as bugs. When a subagent reports something as "critical" or "buggy", read the actual code lines before including it in the plan. Examples: LangGraph `ainvoke(None)` flagged as bug (correct API); reviewer subagent flagged RLS as missing without reading the migration SQL — it was already there. **Specific failure mode**: reviewer/research subagents don't automatically read adjacent files (migrations, schemas, config). A CRITICAL security flag from a subagent is only confirmed after checking the actual evidence file yourself. (confidence: HIGH, source: multiple projects — 3 sessions, date: 2026-03-09)
- **Search ALL injection points, not just the obvious one**: When modifying how data is processed, always grep for ALL places that code path is called. Easy to miss fallback paths and leave an optimization half-done. Pattern confirmed 3×: same issue for guidelines injection, RAG config params, and retriever call sites. (confidence: HIGH, source: multiple projects — 3 sessions, date: 2026-03-11)
- **`if x:` truthiness guard silently skips falsy-but-valid values**: Empty string `""`, `0`, and `False` are all falsy but can be valid IDs/values. Use `if x is not None:` when guarding on presence, not `if x:`. Example: `if node_ids and session_id:` skipped detection when `session_id=""`. (confidence: HIGH, source: multiple projects — 2 variants, date: 2026-03-09)
- **`URLSearchParams.size` is unreliable across Node versions**: `.size` getter was added in Node 19 — not available in Node 18 or earlier. Even Node 20 environments (e.g. Docker alpine) can behave unexpectedly. Always use `params.toString()` truthiness (`const qs = params.toString(); url + (qs ? '?' + qs : '')`) instead of `params.size`. (confidence: HIGH, source: confirmed — caused runtime 500, date: 2026-03-14)
- **Restart dev servers after ANY code change before declaring done**: Both Next.js (Turbopack) and Go (`go run .`) require manual restart to pick up new files/routes. Turbopack may not detect newly created page directories — returns 500. Go binary never hot-reloads — new routes return 404 until restart. **BLOCKING**: After implementing backend/frontend changes, always (1) restart affected server, (2) verify the new endpoint/page responds with curl, (3) THEN tell user to test. Kill first: `kill $(lsof -ti :PORT)`. Known triggers: new file created while dev server runs, new route added to Go mux, `npm run build` while Turbopack runs. (confidence: CRITICAL, source: confirmed — 7 occurrences across 4 sessions on a Go + Next.js project, date: 2026-03-14)
- **CORS `ERR_FAILED` + "no headers" = backend crashed before sending response**: When a CORS error shows no response headers (not even a 500), the issue is NOT CORS misconfiguration — it's a backend crash. Starlette's CORSMiddleware doesn't add CORS headers when inner middleware raises an unhandled exception. Diagnosis: (1) OPTIONS preflight succeeds → CORS config is fine; (2) actual POST/GET fails with ERR_FAILED → crash in handler. Fix: find the AttributeError/crash in backend logs, not the CORS config. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **Fix attribute chain errors by reading the class definition first**: When `obj.foo.bar` raises AttributeError, read the class at its definition (not callers) to find the real attribute name. Guessing one level at a time wastes cycles. (confidence: HIGH, source: multiple projects — 2 rounds of guessing before reading class, date: 2026-03-09)
- **Reproduce the user's exact reported scenario before declaring a fix**: When a user reports a bug in a specific path (authenticated route, specific URL, specific stateful interaction), do NOT declare success after testing only the easy/default/guest path. Common failure mode: 1) make change, 2) reload as guest / default state, 3) "looks fixed!", 4) user reports "still broken", 5) realize the actual reported scenario was never tested — there's a second, deeper bug only visible on the reported path. Cost: 2+ extra cycles and credibility hit. Discipline: before claiming a fix, write out the user's exact reproduction (URL + auth state + interaction sequence) and walk through each step specifically. Two distinct projects have hit the same shape: (a) CSP fix verified on guest path missed the authenticated bug; (b) auto-save hook wired but never actually triggered in the real UI flow. Adjacent to the "verify trigger path end-to-end" rule for hooks. (confidence: HIGH, source: confirmed across 2 projects, date: 2026-05-07)
- **Missing API calls in the network tab reveal which gate is blocking**: When debugging stuck UI (spinner, missing list, half-rendered section), enumerate the API calls the code SHOULD make (read the component + its loader functions), then diff against the network tab's actual calls. The endpoint that's missing reveals the call-site that didn't fire — usually a guard, conditional, or effect that returned early. Faster than instrumenting components with logs because it works at the boundary, not inside the render tree. Especially effective when the symptom is "nothing visible happened" — the absence of an HTTP request is louder than the absence of a console log. (confidence: MED, source: 1 project but generic technique, date: 2026-05-07)

## React Patterns

- **Array data from APIs/props must be null-guarded with `?? []` or `= []`**: Go nil slices serialize to JSON `null` (not `[]`). Any other backend that returns `null` for empty arrays causes `TypeError: Cannot read properties of null (reading 'length')` or `Cannot read properties of undefined (reading 'map')`. Defense: (1) on API response: `setItems(data ?? [])`, (2) on component props: `items: Item[] = []`. Apply to ALL `setState` calls that receive array data from fetch responses, and ALL array props with no guaranteed parent value. Real impact: 8 dashboard pages crashed simultaneously from one null array. (confidence: HIGH, source: confirmed across 2 projects — 3+ sessions, date: 2026-03-28)
- **Lucide icon names: verify before use** — compound/descriptive names like `LayoutPanelRight`, `PanelLayoutRight` do not exist. Real names are short: `PanelLeft`, `PanelRight`, `PanelTop`, `PanelBottom`. Verify with: `node -e "const l = require('./node_modules/lucide-react'); console.log(!!l.PanelRight)"`. (confidence: HIGH, source: multiple projects — 2 separate sessions, date: 2026-03-10)
- **Optional `className` for flexible-width components**: When a component has a hardcoded width (e.g. `w-[400px]`), add `className?: string` prop and use `className ?? 'w-[400px] ...'` as the root element's class. Existing consumers are unaffected; callers that need full-width or overlay can override freely. (confidence: MED, source: multiple projects, date: 2026-03-10)
- **Grep ALL usages of any symbol before removing it**: Before deleting a state variable, import, prop, or exported function, grep the ENTIRE file (or codebase) for all references — including setters (`setFoo`), secondary uses of the same import, and downstream consumers. Confirmed causes: `MapPin is not defined` (import removal, 2×), `Search is not defined` (import removal), stale setter crash. Use: `grep -n "symbolName" file.tsx` before any deletion. (confidence: HIGH, source: multiple projects — 6+ occurrences across several projects, date: 2026-03-09)
- **Ref-for-latest-value in async callbacks**: When a callback closed over state will be called asynchronously (WS `onmessage`, MediaRecorder `onstop`, `setTimeout`, audio `onended`), use a ref (`valueRef.current = value`) synced in the render body so the callback always reads the current value. State is stale inside closures; refs are not. (confidence: HIGH, source: multiple projects — voice + WebSocket handlers, date: 2026-03-09)
- **Recursive async hook restart needs a function ref**: For hooks that restart themselves (continuous recording, polling loops), store `startFnRef.current = startFn` after `useCallback`, then call `startFnRef.current()` inside async callbacks (`onstop`, `onended`). Calling the function directly from inside its own closure causes a stale reference to the initial version. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **Two restart sites for continuous audio/voice loops**: Auto-restart after a successful round goes in `audio.onended`. Auto-restart after an empty/silent round must go in the `onstop` handler itself (with a shorter delay). Missing either site silently kills the loop. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **`useSearchParams()` requires `<Suspense>` boundary in Next.js App Router**: Components using `useSearchParams()` must be wrapped in `<Suspense>` — build fails at static generation without it. Split into a client component (with `useSearchParams`) imported by a server component that wraps it in `<Suspense fallback={...}>`. (confidence: HIGH, source: confirmed across 2 projects, date: 2026-03-14)
- **React Context value-identity trap: `useSyncExternalStore` for external mutable stores**: `<Provider value={store}>` with a stable `store` reference (e.g. `useMemo(create, [])`) does NOT re-render consumers via Context alone — React's `Object.is` check skips because the value didn't change. Wiring the store's mutations to the Provider's `setState` doesn't help if the same store reference passes through. Fix: maintain a `version: number` on the store that increments on every `emit()`, expose `subscribe(cb)` and `getVersion()`, and consume via `useSyncExternalStore(store.subscribe, store.getVersion)` in the hook. This is the React-18 idiomatic pattern for external mutable stores. Plain `useReducer + useEffect(subscribe)` looks correct but only re-renders the Provider, not sibling consumers of the same Context. (confidence: HIGH, source: 1 project but applies to any React 18+ with mutable external store + Context, date: 2026-05-10)
- **Compound interactive row (select + secondary action): outer `<div>` + sibling `<button>` elements — no nested buttons**: HTML disallows `<button>` inside `<button>`. When an existing list row or chip `<button>` needs a second action (e.g. a delete ×), restructure as: outer `<div className="existing-class">` (inherits all CSS) + selection `<button style={{ flex: 1 }}>` + action `<button>`. Each button handles its own click; no `stopPropagation` needed. The div takes the background/border-radius styling via the existing CSS class. (confidence: HIGH, source: 1 project — applied identically in 2 components same session, date: 2026-05-22)
- **`useMutation.onSuccess`: read from pre-mutation state BEFORE calling `queryClient.invalidateQueries()`**: When `onSuccess` reads from component state (e.g. `userTags.find(tg => tg.id === id)`) to determine side-effects (e.g. which filter to reset), it correctly reads the old snapshot because `invalidateQueries` is async — the refetch hasn't fired yet when `onSuccess` runs. This ordering is intentional and correct, but looks like a bug to future readers. Always add a one-line comment: `// read from pre-mutation snapshot before invalidation triggers refetch`. (confidence: HIGH, source: 1 project — reviewer flagged it as potentially stale, date: 2026-05-22)
- **Destructive-action confirmation: never morph the trigger into Confirm at the same screen coordinates**: A single user gesture — mouse double-click OR Enter/Space held — fires twice. Click 1 morphs the button, click 2 lands on the (autoFocused) Confirm at the same `(x, y)`, silently bypassing confirmation. Whole point of the confirmation step is defeated. Place the *safe* action (Cancel) at the original trigger coordinates with `flex: 1` and `autoFocus`; the destructive Confirm must require deliberate cursor movement away from the original position. Verify with `document.elementFromPoint(originalCx, originalCy) === safe-action-id`. /rplan's User Role Coverage edge-case checklist for any destructive UI must enumerate BOTH "keydown spam (Enter/Space held)" AND "mouse double-click at trigger coords" as named cases — covering only one is incomplete. (confidence: HIGH, source: 1 project but generic UI-safety rule, date: 2026-05-10)
- **Zustand v5 `persist` `onRehydrateStorage`: never mutate `state` directly — go through `set()`**: Inside the rehydrate callback, `state.foo = bar` does NOT notify subscribers in zustand v5 (worked in v4; silently broken in v5). The persist middleware passes a snapshot-like reference; only `set()` or store actions that call `set()` internally trigger re-renders. Symptom: persisted state propagates *partially* — keys touched by other `set()` calls (e.g. a side-effect action's `set({ isLoading: true })`) become visible, but pure-mutated keys never reach React. Real-world manifestation: `isHydrated` stays `false` from the component's view → effects gated on it never fire → stuck spinners and `{isHydrated && ...}` ternaries collapsing to `null`. Same root cause can present as multiple unrelated visual bugs in different components — grep ALL subscribers of the suspect flag, don't fix one symptom in isolation. Fix: expose an internal action like `_markHydrated(...)` that calls `set({ ..., isHydrated: true })`, then `state._markHydrated(...)` from the rehydrate callback — the action is bound to the same `set` from `create()`, so subscribers fire. (confidence: HIGH, source: 1 project but applies to any zustand v5 + persist setup, date: 2026-05-07)

## Next.js App Router

- **Same-segment navigation does NOT remount client components**: Navigating between `/content/movie-a` → `/content/movie-b` (same `[slug]` route) keeps the component mounted. `params.slug` changes in-place; all `useState` persists. Any state that should reset between "pages" (e.g. resume position, scroll position, fetched data) must be explicitly reset via a `useEffect` that depends on the route param. (confidence: MED, source: content streaming project — resume playback bug, date: 2026-03-19)
- **Turbopack dev-server caches stale bundle content in three distinct symptom families**: (a) **Stale chunk execution** — Turbopack reuses the chunk URL after a content edit (the chunk name is path-based, not content-hashed); the browser's HTTP cache (and Playwright's HTTP cache) hold the old JS. Hard reload doesn't always bust it. Fix from a Playwright spec: `await page.route('**/*chunk_hash*', r => r.fetch({headers:{'Cache-Control':'no-cache'}}))` before navigation, or `fetch(url, {cache:'reload'})`. (b) **HMR misses newly-added exports** — adding a new method to a frequently-imported large file (60KB+ `services/api.ts` style) and the browser still throws `[exportedObject].newMethod is not a function`. The grep-confirmable code change exists; the bundle didn't pick it up. Fix: `touch <file>` to retrigger HMR + Cmd+Shift+R hard refresh; if still stale, kill `next dev` and restart (`.next` cache desync). (c) **Project-supplied `Cache-Control: immutable` on `/_next/static/:path*`** — a `headers()` rule in `next.config.ts` that sets `public, max-age=31536000, immutable` (common copy-paste from prod CDN guidance) applies to dev too. Combined with (a) — same chunk URL across recompiles — this freezes the running tab forever on the first bundle the browser ever fetched: `nohup npm run dev`, `rm -rf .next`, full restart, none of it makes the browser re-fetch. The dev server prints a warning: "Custom Cache-Control headers detected for the following routes: /_next/static/:path*". Fix: gate that header rule on `!isDev` and emit `no-store` (alone — `must-revalidate` is redundant when paired with `no-store`) in dev. Symptom-to-root-cause shortcut: stale execution → cache-bust the chunk; missing export → force HMR rebuild; **chunk never re-fetches despite `cache: 'no-store'`** → inspect `next.config.ts` `headers()` for an immutable rule. (confidence: HIGH, source: confirmed 3× on same project across 3 sessions, dates: 2026-04-19 + 2026-05-06 + 2026-05-24)
- **SSR `{!user && <X aria-…>}` gates with cookie-based auth cause un-patchable hydration mismatches in React 19 / Next 16**: When `useAuth()` reads the auth token from `document.cookie` (client-only), `user` is `null` during SSR and `truthy` after the first client mount. A conditional render like `{!user && <div aria-label="…">…</div>}` renders the element on the server but expects it gone on the client — React detects the **attribute-level mismatch** and emits `"A tree hydrated but some attributes of the server rendered HTML didn't match the client properties. This won't be patched up."`. The SSR markup stays in the DOM alongside the user-truthy branches. Diagnostic symptom: both `{user && A}` AND `{!user && B}` appear in the DOM simultaneously (logically impossible from current source) — exactly the signal that says "this is hydration, not stale bundle". Fix: gate with a `mounted` boolean (`const [mounted, setMounted] = useState(false); useEffect(() => setMounted(true), [])`) so SSR + first client render both produce nothing (`{mounted && !user && X}`), then post-mount the useEffect flips it and the gate evaluates against the resolved `user`. The pattern is already used in many codebases for the cart-badge counter `{mounted && totalItems > 0 && …}` — extend it to every `!user`/`user`-attribute-bearing conditional you add. (confidence: HIGH, source: 1 project but applies to any Next.js SSR + cookie/localStorage auth, date: 2026-05-24)
- **Next.js 15+ dev + Turbopack + React 19 require `'unsafe-eval'` in CSP `script-src`**: React's dev runtime uses `eval()` for HMR, source maps, and stack reconstruction. If the project ships its own CSP header (e.g. via `next.config.ts` `headers()`), missing `'unsafe-eval'` crashes the dev client mid-hydration on hard refresh — symptom is a cryptic "this page couldn't load" overlay AND the UI gets stuck in a half-mounted state (spinners that never resolve, conditionally-rendered sections that disappear). Console points right at it: `[ERROR] eval() is not supported in this environment...React requires eval() in development mode`. (confidence: HIGH, source: 1 project but applies to any Next.js 15+ project shipping its own CSP, date: 2026-05-07)

## React / Frontend Architecture

- **Three-way render gate for async-resolved content**: When a component renders differently based on async state, use three branches: `null → Skeleton`, `resolved + data → Component`, `resolved + no-data → Fallback`. Never use a flat AND gate (`resolved && data ? <X> : <Fallback>`) — this incorrectly shows the fallback during loading. Template: `{state === null ? <Skeleton /> : data ? <Component /> : <Fallback />}`. (confidence: MED, source: content streaming project — resume playback, date: 2026-03-19)
- **Auth `isLoading` race — `isAuthenticated` starts `false` during token refresh**: Any `useEffect` that branches on `isAuthenticated` must also gate on `!isLoading` (or `!authLoading`). On mount, `isAuthenticated=false` AND `isLoading=true` — this is "unknown", not "logged out". If the effect fires before `refreshToken()` resolves, it executes the anonymous branch for every authenticated user. Guard: `if (isLoading) return;` as the first line in any auth-dependent effect. (confidence: MED, source: content streaming project — auth race during playback resume, date: 2026-03-19)
- **Callback/render props to avoid cross-feature imports**: When Feature A needs to render or interact with Feature B, use render props (`actionSlot?: React.ReactNode`) or callback props (`onTimeUpdate?: (currentTime, duration) => void`) instead of direct imports. The parent in `app/` orchestrates — it passes Feature B's component via prop to Feature A, which renders it without importing. Keeps features decoupled and independently testable. (confidence: HIGH, source: confirmed — 3 occurrences in one project (watchlist button, video player, content card), date: 2026-03-19)

## Go

- **`go test ./...` is the real verification gate, not `go build ./...`**: `go build` compiles production code but skips test files entirely. When an interface gains new methods or a service signature changes, `go build ./cmd/server` still passes — but `go test ./...` fails because mock structs and test call sites are stale. Always run `go test` (not just `go build`) after changing interfaces, service constructors, or exported function signatures. (confidence: HIGH, source: confirmed across 2 projects (Gin radix tree + Go ServeMux), date: 2026-03-19)

(confidence: HIGH, source: pre-existing bug caught in code review, date: 2026-03-30)

- **Local vs Docker process identity — always verify which binary is serving**: When debugging unexpected 404/500 on a Go+Docker project, the first step is `lsof -i :PORT` to identify whether a local `go run` or Docker container is serving. (confidence: HIGH, source: 1 project — caught by fresh-context reviewer, date: 2026-05-22)

## Architecture

- **Global-first design**: Build frameworks in `~/.claude/` (applies everywhere), then scaffold project-specific layers via `/init-env`. Avoid project-only solutions when the pattern is reusable. (confidence: HIGH, source: multiple projects, date: 2026-03-08)
- **PostgreSQL CHECK constraint modification = DROP + re-ADD**: CHECK constraints cannot be ALTERed in-place. ## Python / API

- **Bulk string replacement breaks Python implicit concatenation**: Python fuses adjacent string literals at compile time (`"str1" "str2"` → one string). Replacing only `"str1"` with a constant drops the implicit join — `CONST "str2"` is a SyntaxError (or silently wrong at the value level). Before doing any bulk string find-replace: scan the surrounding context for adjacent literals. If found, use explicit `+` concatenation after substitution: `CONST + "str2"`. Most common source of breakage: auto-refactor scripts that don't read multi-line context. (confidence: HIGH, source: SonarQube S1192 bulk fix session, date: 2026-05-22)
- **Script insertion at "last import line" fails for multi-line parenthetical imports**: A script that finds the last line matching `^from … import` and inserts after it will land INSIDE an open parenthetical block like `from app.schemas import (\n    A,\n<INSERT>\n    B\n)` → SyntaxError. Must track paren/bracket depth and only insert when depth is zero. Template: iterate lines, maintain `depth += open - close`; insert only when `depth == 0 and re.match(r'^from |^import ', line)` and the NEXT non-empty line is not another import. (confidence: HIGH, source: SonarQube S1192 bulk fix session, date: 2026-05-22)
- **`python -m py_compile file.py && echo OK` is the fastest syntax gate after scripted file transforms**: Run it on every touched file before `git add`. Catches self-referential constant assignments (`CONST = CONST`), decorator misplacement, and truncated string replacements in <1s. Cheaper than a full `pytest` run and catches the class of bugs that scripted bulk edits most commonly produce. (confidence: HIGH, source: 2 SonarQube bulk-fix sessions, date: 2026-05-22)
- **Pydantic response models must not inherit input validators**: Response schemas with `min_length`, `regex`, or other input constraints crash the entire list endpoint if ANY single DB row violates the constraint — one bad row = 500 for all users. Keep strict validation on input schemas only; response models should be lenient. (confidence: HIGH, source: production incident — list endpoint 500, date: 2026-03-09)
- **`server_default` required for non-nullable columns on existing tables**: When adding a non-nullable column to a table that already has rows, set both `default=` (Python ORM) AND `server_default=` (DB-level). Missing `server_default` causes the migration to fail on non-empty tables even if `default=` is set. (confidence: HIGH, source: multiple projects — Alembic + SQLAlchemy, date: 2026-03-09)
- **Alembic `--autogenerate` picks up ALL schema drift, not just intended changes**: Always inspect and clean generated migrations before applying — remove unintended table/column changes that drifted since last migration. Apply only the target change. (confidence: HIGH, source: multiple projects — confirmed across 2 codebases, date: 2026-03-09)
- **`smtplib.SMTP(host, port)` has NO default timeout — always pass `timeout=10`**: Default is OS-level socket timeout (potentially minutes on Linux, infinite on some configs). If the SMTP relay is unreachable, the worker hangs until gunicorn's worker-timeout kills it (default 30s). Combined with `await` of a sync smtplib call inside a request handler, that surfaces as a 502 *after* `db.commit()` already changed state — silent data divergence. One-line fix: `smtplib.SMTP(host, port, timeout=10)`. Same applies to `smtplib.SMTP_SSL`. (confidence: HIGH, source: 1 project + applies broadly, date: 2026-05-03)
- **FastAPI `BackgroundTasks` runs SYNCHRONOUSLY on the same event loop after the response**: It does NOT take blocking I/O off the loop — it just defers it past the response send. If your background callable is sync (smtplib, sync HTTP libraries), the loop is still pinned for the call duration after the response is sent, blocking other requests on the same worker. To actually run off-loop: (a) wrap the sync call inside `asyncio.to_thread(fn, *args)` in your background task, OR (b) declare the background callable as plain `def` (not `async def`) — FastAPI runs sync background callables in a threadpool via `run_in_threadpool`. Inline `await sync_fn()` at low volume (<5/day) is acceptable if the sync call has a short timeout cap. (confidence: HIGH, source: 1 project + applies to any FastAPI app, date: 2026-05-03)
- **`pg_insert(...).on_conflict_do_nothing(index_elements=['x'])` against a partial UNIQUE index requires `index_where=`**: Postgres needs the partial-index predicate to match the index as the conflict target. With only `index_elements`, runtime raises SQLSTATE 42P10 "no unique or exclusion constraint matching the ON CONFLICT specification". Correct: `pg_insert(Model).on_conflict_do_nothing(index_elements=['user_id'], index_where=Model.user_id.isnot(None))`. The pseudo-SQL form `ON CONFLICT (user_id) WHERE user_id IS NOT NULL DO NOTHING` is correct; the SQLAlchemy call must mirror both clauses. (confidence: HIGH, source: 1 project but applies to all SQLAlchemy + Postgres, date: 2026-05-03)
- **`Base.metadata.create_all` builds test schema from MODEL definitions, NOT from migrations**: Tests that use `await conn.run_sync(Base.metadata.create_all)` create a synthetic schema that includes every column/constraint declared on the model — even ones that were never migrated to production. Model→migration drift (e.g. an uncommitted `UniqueConstraint` in `__table_args__`) passes tests but breaks in prod. When verifying schema-level invariants (unique constraints, CHECK constraints, foreign keys), always run `\d table` against the live DB or against an alembic-built test DB — never trust model declarations alone. (confidence: HIGH, source: 1 project + applies to any SQLAlchemy + alembic project, date: 2026-05-03)
- **Alembic `upgrade()` needs an IF NOT EXISTS guard when the table may already exist**: If a table was created manually (dev hotfix, prior partial migration, or ORM auto-create at startup) before the migration is written, `op.create_table()` raises `DuplicateTableError`. Applies to both `op.create_table` and `op.create_index`. (confidence: HIGH, source: confirmed 1 project; applies to any Alembic + Postgres/SQLite project, date: 2026-05-21)
- **FastAPI `app.dependency_overrides[get_db]` does NOT patch `async_session_factory` direct callers**: `dependency_overrides` only intercepts code that goes through FastAPI's DI graph (i.e. `Depends(get_db)`). Fix: `patch("module.async_session_factory", in_memory_factory)` at the test level for each module that uses the factory directly. (confidence: HIGH, source: confirmed across 2 projects — same pattern needed for background tasks and non-request lifespan hooks, date: 2026-05-21)

## Python Async

- **`asyncio.to_thread()` / `run_in_executor()` for any synchronous call in async context**: Never call synchronous operations directly in an async handler — blocks the event loop for all concurrent requests. Rule: **CPU-bound sync (ML inference, compression)** → `await asyncio.to_thread(fn, *args)`. **I/O-bound sync SDK (boto3, stripe, any sync HTTP client)** → `await loop.run_in_executor(None, partial(fn, **kwargs))`. For startup preloading, use `loop.run_in_executor(None, preload_fn)` in the lifespan handler to avoid cold-start delay. (confidence: HIGH, source: multiple projects — 2 different contexts confirmed, date: 2026-03-11)
- **`except Exception` misses `CancelledError` in Python 3.8+**: `CancelledError` is `BaseException`, not `Exception`. In startup/lifespan safety nets and reconnect loops, always use `except BaseException` to prevent silent crash propagation. Real production impact: FastAPI backend crashed at startup every time an external service was unreachable. (confidence: HIGH, source: multiple projects — lifespan + reconnect patterns, date: 2026-03-10)
- **anyio cancel scope must be entered/exited in the same asyncio Task**: When `anyio.create_task_group()` is used inside an async context manager, entering via `__aenter__()` in one task and exiting in another raises `RuntimeError: Attempted to exit cancel scope in a different task than it was entered in`. Fix: run each anyio-dependent operation in its own `asyncio.create_task()`. (confidence: HIGH, source: multiple projects — MCP/SSE client pattern, date: 2026-03-10)
- **Async SQLAlchemy: every relationship a service reads must be explicitly eager-loaded by every caller**: When a pure service function reads `obj.foo.bar`, every endpoint/caller that hands it an `obj` must include `selectinload(Model.foo)` (or equivalent) in its query. Async sessions raise `MissingGreenlet` on lazy-load. **Identity-map can mask the bug** — if the parent of `obj.foo` is already loaded for another reason (e.g. you walked `Parent → children`, and `children[i].parent` resolves via session cache), it works without IO until a refactor changes the load path. Then it explodes in production. Three known triggers: (1) `expire_all()` in async context forces sync lazy-load; (2) downstream service reading nested relationship that wasn't in the caller's selectinload chain; (3) **`db.commit()` with default `expire_on_commit=True` expires every attribute on the loaded object — `model_validate(obj)` immediately afterward triggers MissingGreenlet on EVERY field** (not just relationships). Fix for case (3): `await db.refresh(obj, ['relationship_a', 'relationship_b'])` after commit before serializing, OR re-fetch the row with a fresh `select(...).options(selectinload(...))`. Always trace: which fields does the service touch? Each one needs an explicit selectinload at the call site, AND any post-commit serialization needs an explicit refresh. (confidence: HIGH, source: confirmed 4× across 3 sessions on same backend project, date: 2026-05-03)

## MCP Playwright

- **Use snapshot refs over text selectors in crowded layouts**: When multiple elements share the same visible text (e.g., a filter pill "Recipes" and a dropdown option "Recipes" both in the DOM), `locator('text=Recipes')` causes "strict mode violation". Capture a fresh snapshot, identify the exact `[ref=eNNN]` for the target, and click by ref. Snapshot refs are unambiguous; text selectors are not when the same label appears in multiple components. (confidence: HIGH, source: Slate slice 9 — TagPicker click hit NoteList filter instead of dropdown, date: 2026-05-07)
- **Interact with modals/overlays via browser_evaluate + querySelector**: Fixed-position overlays (bottom sheets, modals, popovers) are sometimes absent or flattened in the accessibility snapshot tree. Use `browser_evaluate` with `document.querySelector('[style*="position: fixed"]')` to find the overlay, then `.querySelectorAll('button')` + `.click()` to interact. More reliable than snapshot-based targeting for dynamically-rendered overlays. (confidence: HIGH, source: Slate slice 9 — MobileTagPicker bottom sheet, date: 2026-05-07)
- **`PLAYWRIGHT_JSON_OUTPUT_NAME` env-var bypasses rtk stdout truncation**: rtk's stdout passthrough mangles Playwright JSON output mid-string at ~14KB, breaking `json.loads()`. The reliable parse path is `PLAYWRIGHT_JSON_OUTPUT_NAME=/tmp/x.json npx playwright test ... --reporter=json > /dev/null 2>&1; python3 -c "import json; r = json.load(open('/tmp/x.json'))"` — Playwright writes the full untruncated JSON to the env-named file regardless of stdout. Complements the `--reporter=line` workaround (single-pass list output rtk passes through cleanly) — use line for human-readable runs, env-var JSON for parseable per-test status. (confidence: HIGH, source: confirmed across 2 sessions on 1 project; pattern is stack-portable to any rtk + Playwright setup, date: 2026-05-06 → 2026-05-08)
- **Programmatic input value changes need the native prototype setter to trigger React onChange**: React 18+ controlled `<input>`/`<textarea>` listens on the prototype `value` setter, not on direct `el.value = x`. Setting `el.value = "foo"` then dispatching `new Event('change')` updates the DOM visually but DOES NOT update React state — the synthetic onChange handler never fires. Same failure for Playwright's `browser_type` / `pressSequentially` against controlled inputs (DOM updates, React state stays empty, form submission sends old/empty value). Fix: `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set.call(el, value); el.dispatchEvent(new Event('input', { bubbles: true }))`. Note: must use `'input'` event (not `'change'`) and `bubbles: true`. For `<textarea>`, use `HTMLTextAreaElement.prototype` instead. Detection: if the field's value visually updates but a `submit` button stays disabled (controlled-form validation didn't see the change) or the API receives an empty string, this is the bug. (confidence: HIGH, source: confirmed across 2 projects, date: 2026-04-17 → 2026-05-06)
- **`browser_evaluate` runs as plain JavaScript, not TypeScript**: TS syntax in the function body (type casts like `(x as any).foo`, type annotations like `: string`, `as const`) throws `SyntaxError: Unexpected identifier`. Strip every TS construct before passing the function. Use `el.style.getPropertyValue('-webkit-line-clamp')` instead of casting to `any`; use runtime `typeof`/`in` checks instead of type guards. (confidence: HIGH, source: 1 project but applies to all MCP Playwright callers, date: 2026-05-08)
- **Chrome user-data-dir lock recovery**: After `browser_close` returns "no open tabs", a stale Chrome process can still hold `~/Library/Caches/ms-playwright/mcp-chrome-*/` and the next `browser_navigate` fails with "Browser is already in use". The lock file `SingletonLock` is a symlink whose target is `<hostname>-<PID>`. Recovery: `pgrep -lf mcp-chrome` to find the live PID, `ps -p <PID>` to confirm it's still running, then `pkill -9` (with user consent). Do NOT blindly add `--isolated` — it loses state across QA steps. Do NOT just delete the lock — a live Chrome will recreate it. (confidence: HIGH, source: confirmed 2× on same project, date: 2026-05-08 → 2026-05-10)
- **`browser_navigate(url)` is a hard reload — wipes in-memory state**: For QA flows that depend on persisted-across-navigation state (Zustand, Context, refs without persist middleware), use SPA navigation (click an in-app tab via `getByRole('button')` etc.) to preserve state. A failing assertion that immediately follows `browser_navigate` may be a test-harness artifact, not a real bug — re-run via SPA nav before filing. Document the divergence in plan Branch Points if false-fail risk is high. (confidence: HIGH, source: 1 project but applies to all MCP Playwright users, date: 2026-05-10)
- **MCP Playwright HTTP cache survives `browser_close` — use CDP `Network.setCacheDisabled` for true cache bypass**: The Chromium context's HTTP cache persists across tabs (and across `browser_navigate` calls), so when a dev server's `Cache-Control` header *changes* (e.g. `immutable` → `no-store`), the browser still serves the old entry it cached under the old header. Symptom: the dev server now sends correct `Cache-Control: no-store`, `curl` returns the new chunk content, `fetch(url, {cache:'no-store'})` from inside the page returns the new content, but `document.querySelector` STILL reflects the old running JS module. Cause: the V8 / module cache references the chunk *already loaded into memory* under the old policy. Fix: use `browser_run_code_unsafe` to open a CDP session and disable cache + purge it before reloading: ```js const client = await page.context().newCDPSession(page); await client.send('Network.setCacheDisabled', { cacheDisabled: true }); await client.send('Network.clearBrowserCache'); await page.reload({ waitUntil: 'networkidle' });```. This is the only reliable bypass when (a) dev cache headers just changed, or (b) chunk URLs are path-based and content has changed in-place (Turbopack — see Next.js App Router section). Cheap diagnostic: if your `evaluate` shows the React fiber's `memoizedState` already has the new auth value but the DOM still renders the old conditional branch, the running JS module is the problem — apply the CDP fix. (confidence: HIGH, source: 1 project but applies to any MCP Playwright + Next.js/Vite dev-cache change, date: 2026-05-24)
- **`window.fetch` counter > network log for "fired exactly once" assertions**: `browser_network_requests` can show one application-level `fetch` as two numbered entries (request + response, or a Vite proxy hop) — counting log entries is unreliable proof of "fired once". Install a wrapper before the action: `const orig = window.fetch; window.__fetchCount = 0; window.fetch = (u, o) => { if ((o?.method ?? 'GET').toUpperCase() === 'DELETE') window.__fetchCount++; return orig(u, o); };`, then assert `window.__fetchCount === 1`. The counter is the application-level ground truth. (confidence: HIGH, source: 1 project but applies to all MCP Playwright + write-once QA, date: 2026-05-10)

## Vite

- **Vite dev module graph can serve a stale source file even after `npm run build` succeeds**: A long-lived browser tab can hold the old module while the dist build is up-to-date. Symptom: new `data-testid` attributes ARE queryable in the DOM (so partial HMR happened) but new state-machine behaviour doesn't fire. Hard-navigate with a fresh query-string (`?_t=cachebust`) — this forces a full re-fetch. When MCP-driven QA shows behaviour inconsistent with the source code, hard-navigate with `?_t=...` *before* assuming a real bug. Mirrors the Turbopack stale-chunk pattern. (confidence: HIGH, source: 1 project but applies to any Vite + long-lived browser/MCP tab, date: 2026-05-10)

## MCP Servers

- **MCP servers must start BEFORE the backend for auto-reconnect**: `reconnect_all` runs once at startup. If any MCP server is down at that moment, its tools are silently missing at runtime (tool returns "not found"). Correct start order: MCP servers first, then backend. If order was wrong: restart backend or reconnect via UI. (confidence: HIGH, source: multiple projects — repeated across 2 sessions, date: 2026-03-10)
- **`list[dict]` params generate `additionalProperties:true` schema → LLM skips them**: FastMCP infers JSON Schema from function type hints. `list[dict]` yields `{"items": {}, "additionalProperties": true}` — LLM treats it as optional freeform and often omits it entirely. Use Pydantic models so FastMCP generates a full named schema with required fields the LLM must fill. (confidence: HIGH, source: multiple projects — tool param always missing, date: 2026-03-09)
- **LLM constructs IDs from known fields instead of using returned IDs**: When search results return opaque IDs, LLM in subsequent turns often reconstructs a plausible-looking ID rather than copying the actual returned value. Two defenses: (1) make IDs human-readable with embedded context, (2) add fuzzy fallback lookup on the server side. (confidence: HIGH, source: multiple projects, date: 2026-03-09)
- **FastMCP transport options — SSE vs streamable-HTTP**: SSE (`/sse`) is persistent and simpler to debug but can silently drop mid-session. Streamable-HTTP (`/mcp`, POST per tool call, no persistent connection) is more reliable for tool calls. Default to streamable-HTTP for new MCP servers; use SSE only if client compatibility requires it. (confidence: MED, source: multiple projects — conflicting signals, date: 2026-03-09)
- **FastMCP 3.x schema inspection**: `_tool_manager` attribute was removed in FastMCP 3.x. To inspect generated schemas: `tools = await mcp.list_tools(); print(tools[0].to_mcp_tool().inputSchema)`. Don't use internal attributes; use the public MCP protocol methods. (confidence: HIGH, source: FastMCP 3.x migration, date: 2026-03-09)
- **External pricing/booking APIs return transient offers — always cache with TTL**: Any 3rd-party booking API (Amadeus, Stripe, hotel aggregators) returns offers/prices that expire (typically 15-30 min). Cache the full raw offer object after search (keyed by display ID) so downstream steps (pricing confirmation, booking, seat selection) can reference it. Delete from cache on TTL expiry. (confidence: HIGH, source: multiple projects — external API integration, date: 2026-03-11)
- **Graceful fallback with local IDs for external booking APIs**: When an external booking API call fails (sandbox limits, network error), don't propagate the error — generate a local booking record with UUID-based IDs (`uuid4().hex[:8].upper()`), log a warning, and return success. (confidence: HIGH, source: multiple projects — external API integration, date: 2026-03-11)
- **Aisle-gap algorithm for seat type detection is more reliable than column-letter mapping**: Hardcoded lists of aisle columns (`["C", "D", "G", "H"]`) fail for non-standard configs. Instead, represent layout as `["A","B","C","","D","E","F"]` (empty string = aisle gap) then check `columns[i-1]==""` (left of aisle = AISLE) and `columns[i+1]==""` (right of aisle = AISLE). Works for any aircraft config. (confidence: HIGH, source: seat map implementation, date: 2026-03-09)
