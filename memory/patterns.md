# Cross-Project Learned Patterns

Patterns confirmed across multiple projects and sessions. Updated by `/reflect`.

## Workflow

- **Research > Discuss > Map > Implement**: Never jump to implementation. Establish foundations first — research the domain, discuss with user to align, map the solution, then build. (confidence: HIGH, source: OneIntel, date: 2026-03-08)
- **Subagent size threshold for research**: ≥8 files across frontend+backend → use Explore subagent (one-pass comprehensive context). ≤4 specific, known files → use Read/Grep directly (subagent overhead not worth it; user rejects it). (confidence: HIGH, source: OneIntel — Newme Call Screen + LangGraph Audit + EmbedChat ContentPanel, date: 2026-03-09)
- **Verify code state, not plan file status**: Plan files can say "Draft" or "In Progress" while the code is already fully implemented. Always read the actual source files to verify implementation state before starting — avoids re-doing work. (confidence: MED, source: OneIntel — Plugin Gating + LangGraph Audit, date: 2026-03-09)

## Code Quality

- **Never use `transition-all` on interactive cards/toggles**: Use `transition-colors` or list specific properties. `transition-all` animates width/height/shadow changes causing layout jank, especially in grid layouts. (confidence: HIGH, source: OneIntel Plugin Store, date: 2026-03-08)
- **Tailwind `focus:ring-offset-*` adds real box space**: Avoid on elements inside constrained grids/flexbox — it pushes parent containers wider on focus. Use `focus:ring` without offset, or `focus:outline` instead. (confidence: MED, source: OneIntel, date: 2026-03-08)

## Tools

- **Reading PDFs: WebFetch saves binary, use pdftotext**: WebFetch downloads PDFs as binary to a local path but can't extract text. Install poppler (`brew install poppler`) then run `/opt/homebrew/bin/pdftotext file.pdf -` to extract text. `pdftotext` is NOT in default shell PATH. (confidence: HIGH, source: OneIntel — Anthropic Skills Guide research, date: 2026-03-09)

## Debugging

- **2-strike rule for CSS/layout bugs**: If 2 CSS fixes don't work, STOP guessing. Trace the full chain: what state changed → what component re-rendered → what DOM mounted/unmounted → what caused the layout shift. The bug is often in a parent component, not the element itself. (confidence: HIGH, source: OneIntel Plugin Store — 5 failed attempts before tracing to parent tab bar reflow, date: 2026-03-08)
- **Verify subagent claims before putting them in a plan**: Subagents occasionally misread patterns or flag correct API as bugs. When a subagent reports something as "critical" or "buggy", read the actual code lines before including it in the plan. 4 instances: LangGraph `ainvoke(None)` flagged as bug (correct API), condition_eval.py reported missing features it already had. (confidence: HIGH, source: OneIntel — 2 sessions, date: 2026-03-09)
- **Search ALL injection points, not just the obvious one**: When modifying how data is processed (e.g. how guidelines are injected), always grep for ALL places that code path is called. LangGraph had `process()` AND `_simple_chat()` both loading guidelines — easy to miss the fallback path and leave the optimization half-done. **Extended (3×):** Same pattern for new RAG config params — LangGraph has TWO independent auto-RAG call sites (workflow path + simple_chat path). When adding any new `retrieve()` kwarg, grep for ALL `_retriever.retrieve(` call sites and the sibling param (e.g. `rerank_strategy`) to find them all. Confirmed: Progressive Guidelines + Cross-Encoder + Chunk Quality Flags. (confidence: HIGH, source: OneIntel — 3 sessions, date: 2026-03-11)
- **`if x:` truthiness guard silently skips falsy-but-valid values**: Empty string `""`, `0`, and `False` are all falsy but can be valid IDs/values. Use `if x is not None:` when guarding on presence, not `if x:`. Found in LangGraph: `if approval_node_ids and session_id:` skipped approval detection for `session_id=""`. (confidence: HIGH, source: OneIntel — 2 variants, date: 2026-03-09)
- **CORS `ERR_FAILED` + "no headers" = backend crashed before sending response**: When a CORS error shows no response headers (not even a 500), the issue is NOT CORS misconfiguration — it's a backend crash. Starlette's CORSMiddleware doesn't add CORS headers when inner middleware raises an unhandled exception. Diagnosis: (1) OPTIONS preflight succeeds → CORS config is fine; (2) actual POST/GET fails with ERR_FAILED → crash in handler. Fix: find the AttributeError/crash in backend logs, not the CORS config. (confidence: HIGH, source: OneIntel MCP Manager — `mcp_gateway.tool_registry` AttributeError crashed before headers, date: 2026-03-09)
- **Fix attribute chain errors by reading the class definition first**: When `obj.foo.bar` raises AttributeError, read the class at its definition (not callers) to find the real attribute name. Guessing one level at a time wastes cycles. Example: `mcp_gateway.tool_registry` → tried `mcp_gateway.has_content_mapping()` (wrong) before reading class and finding `mcp_gateway.registry.has_content_mapping()` (correct). (confidence: HIGH, source: OneIntel — 2 rounds of guessing before reading class, date: 2026-03-09)

## React Patterns

- **Lucide icon names: verify before use** — `LayoutPanelRight`, `PanelLayoutRight`, etc. do not exist. The real names are `PanelLeft`, `PanelRight`, `PanelTop`, `PanelBottom`. Hit this error in 2 separate sessions. Verify with: `node -e "const l = require('./node_modules/lucide-react'); console.log(!!l.PanelRight)"`. Compound/descriptive lucide names are almost always wrong — check the icon list first. (confidence: HIGH, source: OneIntel — 2 sessions EmbedChat + VoiceCall, date: 2026-03-10)
- **Optional `className` for flexible-width components**: When a component has a hardcoded width (e.g. `w-[400px]`), add `className?: string` prop and use `className ?? 'w-[400px] ...'` as the root element's class. Existing consumers are unaffected; callers that need full-width or overlay can override freely. (confidence: MED, source: OneIntel — ContentPanel embed overlay, date: 2026-03-10)
- **Grep ALL usages of state before removing it from a component**: Before deleting `const [foo, setFoo] = useState(...)`, grep the component for both `foo` and `setFoo`. Setters are easily missed — a stray `setFoo(x)` in an unrelated handler causes a runtime "X is not defined" crash. (confidence: HIGH, source: OneIntel MCP Manager — `setMcpLoaded` left in tenant-switch handler after removing state, date: 2026-03-09)
- **Ref-for-latest-value in async callbacks**: When a callback closed over state will be called asynchronously (WS `onmessage`, MediaRecorder `onstop`, `setTimeout`, audio `onended`), use a ref (`valueRef.current = value`) synced in the render body so the callback always reads the current value. State is stale inside closures; refs are not. (confidence: HIGH, source: OneIntel voice chat + antri WS handlers, date: 2026-03-09)
- **Recursive async hook restart needs a function ref**: For hooks that restart themselves (continuous recording, polling loops), store `startFnRef.current = startFn` after `useCallback`, then call `startFnRef.current()` inside async callbacks (`onstop`, `onended`). Calling the function directly from inside its own closure causes a stale reference to the initial version. (confidence: HIGH, source: OneIntel continuous voice chat, date: 2026-03-09)
- **Two restart sites for continuous audio/voice loops**: Auto-restart after a successful round goes in `audio.onended`. Auto-restart after an empty/silent round must go in the `onstop` handler itself (with a shorter delay). Missing either site silently kills the loop. (confidence: HIGH, source: OneIntel — loop died on first silent round, date: 2026-03-09)

## Audio / Voice / AI

- **OpenAI hosted whisper-1 has no tunable server params**: `vad_filter`, `condition_on_previous_text`, `compression_ratio_threshold`, `no_speech_threshold` are only available in self-hosted Whisper/faster-whisper. When using the OpenAI API, all anti-hallucination defense must be client-side. (confidence: HIGH, source: OneIntel deep research, date: 2026-03-09)
- **Never use Whisper `initial_prompt` for continuous voice chat**: Research (OpenAI community + GitHub issues) shows `initial_prompt` causes ~80% fully-hallucinated looping output in continuous contexts. Use hallucination blocklist + VAD + echo cancellation instead. (confidence: HIGH, source: OneIntel + external research, date: 2026-03-09)
- **7-layer client-side anti-hallucination stack for Whisper**: (1) VAD (Silero/@ricky0123/vad-web), (2) echoCancellation+noiseSuppression on getUserMedia, (3) speechDetected RMS threshold flag, (4) hallucination string blocklist (60+ strings, 12+ languages), (5) repetition/loop detector (word count + unique ratio), (6) min cumulative speech duration, (7) consecutive-silence bail-out (3 strikes → pause). First two give the highest ROI. (confidence: HIGH, source: OneIntel research + implementation, date: 2026-03-09)

## Architecture

- **Global-first design**: Build frameworks in ~/.claude/ (applies everywhere), then scaffold project-specific layers via /init-env. Avoid project-only solutions when the pattern is reusable. (confidence: HIGH, source: OneIntel, date: 2026-03-08)

## Tools & Commands

- **Lean CLAUDE.md (<100 lines) with @imports**: Long CLAUDE.md gets ignored as context fills. Keep root file lean, use @imports for details (execution-protocol.md, plan-template.md, project-context.md). (confidence: HIGH, source: OneIntel + 5 external sources, date: 2026-03-08)
- **Three-file settings separation**: .claude/settings.json (committable project hooks), .claude/settings.local.json (gitignored personal permissions), ~/.claude/settings.json (global hooks). Never mix concerns across these files. (confidence: HIGH, source: OneIntel + Claude Code docs, date: 2026-03-08)
- **Background Bash tasks need `bash -c` wrapper**: `cd /path && command` in background mode doesn't persist cwd — the `cd` runs in one shell, the command in another. Use `bash -c 'cd /path && command'` for reliable execution. (confidence: HIGH, source: OneIntel — failed 6+ times across 2 sessions, date: 2026-03-08)
- **rtk hook rewrites ALL commands**: npm, npx, git — everything goes through rtk. To bypass, call binaries directly: `./node_modules/.bin/vite` instead of `npm run dev`. (confidence: HIGH, source: OneIntel, date: 2026-03-08)
- **`git add` requires single-line space-separated args**: Backslash line continuation in Bash tool fails with "pathspec ' '" error — shell interprets each line as a separate command. Always: `git add file1 file2 file3` on one line. (confidence: HIGH, source: OneIntel — 2 sessions, date: 2026-03-09)
- **`rtk proxy <cmd>` bypasses RTK filtering for raw output**: When debugging API calls and RTK strips response bodies, prefix with `rtk proxy` (e.g. `rtk proxy curl -s http://localhost:8100/api/...`) to get the full unfiltered response. Critical for diagnosing "Failed to fetch" errors where the real error is hidden. (confidence: HIGH, source: OneIntel booking MCP debug, date: 2026-03-09)

## Python Async

- **`asyncio.to_thread()` / `run_in_executor()` for any synchronous call in async context**: Never call synchronous operations directly in an async handler — blocks the event loop for all concurrent requests. Rule: **CPU-bound sync (ML inference, compression)** → `await asyncio.to_thread(fn, *args)`. **I/O-bound sync SDK (Amadeus, boto3, stripe, any sync HTTP client)** → `await loop.run_in_executor(None, partial(fn, **kwargs))`. For startup preloading, use `loop.run_in_executor(None, preload_fn)` in the lifespan handler to avoid cold-start delay. Confirmed in 2 different contexts: ML cross-encoder reranking + Amadeus API adapter. (confidence: HIGH, source: OneIntel cross-encoder + Amadeus adapter, date: 2026-03-11)
- **`except Exception` misses `CancelledError` in Python 3.8+**: `CancelledError` is `BaseException`, not `Exception`. In startup/lifespan safety nets and reconnect loops, always use `except BaseException` to prevent silent crash propagation. Real production impact: FastAPI backend crashed at startup every time an MCP server was unreachable because `CancelledError` escaped the `except Exception` handler. (confidence: HIGH, source: OneIntel — backend lifespan + reconnect_all, date: 2026-03-10)
- **anyio cancel scope must be entered/exited in the same asyncio Task**: When `anyio.create_task_group()` is used inside an async context manager (e.g. MCP SSE client), entering via `__aenter__()` in one task and exiting in another raises `RuntimeError: Attempted to exit cancel scope in a different task than it was entered in`. Fix: run each anyio-dependent operation in its own `asyncio.create_task()`. (confidence: HIGH, source: OneIntel — MCP reconnect_all, date: 2026-03-10)

## MCP Servers

- **MCP servers must start BEFORE the backend for auto-reconnect**: `reconnect_all` runs once at startup. If any MCP server is down at that moment, its tools are silently missing at runtime (tool returns "not found"). Correct start order: MCP servers first, then backend. If order was wrong: restart backend or reconnect via UI. (confidence: HIGH, source: OneIntel — repeated across 2 sessions, date: 2026-03-10)
- **`list[dict]` params generate `additionalProperties:true` schema → LLM skips them**: FastMCP infers JSON Schema from function type hints. `list[dict]` yields `{"items": {}, "additionalProperties": true}` — LLM treats it as optional freeform and often omits it entirely. Use Pydantic models (`list[PassengerInput]`) so FastMCP generates a full named schema with required fields the LLM must fill. (confidence: HIGH, source: OneIntel booking MCP — passengers always missing, date: 2026-03-09)
- **LLM constructs IDs from known fields instead of using returned IDs**: When search results return opaque `flight_id`s, LLM in subsequent turns often reconstructs a plausible-looking ID (e.g. `FL-GA123-20260401-1-ECO`) rather than copying the actual returned value. Two defenses: (1) make IDs human-readable with embedded context (`GA123-NRTCGK-20260401-1-ECO`), (2) add fuzzy fallback lookup (extract flight_number+date → scan catalog). (confidence: HIGH, source: OneIntel booking MCP, date: 2026-03-09)
- **FastMCP transport options — SSE vs streamable-HTTP**: SSE (`/sse`) is persistent and simpler to debug but has been observed to silently drop mid-session (shopping MCP). Streamable-HTTP (`/mcp`, POST per tool call, no persistent connection) is more reliable for tool calls. `mcp_gateway.py` auto-detects: URL ending `/sse` → SSE client, any other → streamable-HTTP. Default to streamable-HTTP for new MCP servers; use SSE only if client compatibility requires it. (confidence: MED, source: OneIntel shopping + booking MCP — conflicting signals, date: 2026-03-09)
- **FastMCP 3.x schema inspection**: `_tool_manager` attribute was removed in FastMCP 3.x. To inspect generated schemas: `tools = await mcp.list_tools(); print(tools[0].to_mcp_tool().inputSchema)`. Don't use internal attributes; use the public MCP protocol methods. (confidence: HIGH, source: OneIntel booking MCP, date: 2026-03-09)
- **External pricing/booking APIs return transient offers — always cache with TTL**: Any 3rd-party booking API (Amadeus, Stripe, hotel aggregators) returns offers/prices that expire (typically 15-30 min). Cache the full raw offer object after search (keyed by display ID) so downstream steps (pricing confirmation, booking, seat selection) can reference it. Delete from cache on TTL expiry. Without caching, `book()` has no offer to submit. (confidence: HIGH, source: OneIntel Amadeus adapter, date: 2026-03-11)
- **Graceful fallback with local IDs for external booking APIs**: When an external booking API call fails (sandbox limits, network error), don't propagate the error — generate a local booking record with UUID-based IDs (`uuid4().hex[:8].upper()`), log a warning, and return success. User gets a usable booking record; engineer can inspect logs for the root cause. Applies whenever the MCP server's core value is the booking record, not the specific API's response. (confidence: HIGH, source: OneIntel Amadeus adapter, date: 2026-03-11)
- **Aisle-gap algorithm for seat type detection is more reliable than column-letter mapping**: Hardcoded lists of aisle columns (`["C", "D", "G", "H"]`) fail for non-standard configs. Instead, represent layout as `["A","B","C","","D","E","F"]` (empty string = aisle gap) then check `columns[i-1]==""` (left of aisle = AISLE) and `columns[i+1]==""` (right of aisle = AISLE). Works for any aircraft config. (confidence: HIGH, source: OneIntel booking MCP seat map, date: 2026-03-09)
